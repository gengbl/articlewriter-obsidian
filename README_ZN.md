## ⚠️ 信息披露与安全声明（Disclosures & Security Statement）

**网络请求。** 本插件除 LLM 对话外不进行任何联网活动。所有出站流量仅通过官方 `openai` SDK 发往**你在设置中自行配置的** OpenAI 兼容端点（本地服务如 Ollama / LM Studio / llama.cpp，或 DeepSeek、通义千问 DashScope 等服务商 API）。运行时只会触发三类请求——非流式与流式 chat completions，以及运行「LLM 连接测试」验证端点时的一次 `GET /models`；扫描器标记出的其余请求相关调用点属于打包进 bundle 的 SDK 通用 HTTP 层，本插件不会在其他地方使用它们。**没有任何遥测、统计上报、更新检查，也不连接任何作者自建的服务器。** API Key 由你本人在设置面板输入，随其他插件配置一起保存在你的 vault 本地，只作为认证头发送给你所选的端点；留空时（本地服务的常见情况）以固定占位值（`local-no-auth`）顶替，真实密钥绝不离开你的机器。

**Base64 用法（`atob` / `btoa`）。** 插件自身源码中只有**一处**解码调用：一个 `atob`，把**构建时就打进产物里**的二维码图片（作者联系方式，esbuild 构建时以 data URL 内联）还原成 PNG 写到工作目录《使用说明.md》旁边——纯静态内置资源、不联网、不涉及任何用户数据；插件自身没有任何编码调用。发布产物中出现的所有其它 base64 实例均来自 esbuild 打包进来的第三方库：`yaml` 解析器（其处理 YAML `!!binary` 标签的标准代码）和 openai SDK（通用的 base64 ↔ 二进制缓冲转换辅助函数），只做常规数据格式转换，**未用于混淆 API Key、隐藏 URL 或掩盖任何代码载荷**。构建产物未经压缩混淆，完整可读源码已发布于[仓库](https://github.com/gengbl/articlewriter-obsidian)，如有疑虑请直接审计。

### Vault 遍历披露（Vault Enumeration Disclosure）
本插件通过 Obsidian 标准 `app.vault` API 查看 vault 内的文件结构，范围严格分为两类：
* **用途——全库级「路径」列举（两个小的 UI 选择器）**：(a) 首次使用 / 切换工作目录（`work_dir`）时弹出的文件夹选择器会列出已有文件夹供模糊搜索；该遍历从 vault 根开始但刻意设限——**最深只下探 3 层、最多收集 500 个条目、跳过 `.obsidian/` 等隐藏目录**；(b) 可停靠聊天面板的 @引用候选列表在渲染时调用一次 `vault.getFiles()`，让你能用一个快捷键把 vault 里任意文档引用进 LLM 提示词。两者都只列文件**路径**，当时不读取任何内容。只有你实际操作后才会加载文本：选定文件夹只是为后续本地操作定界；引用某文件则会把其内容并入你自己发起的、发往你所配置模型端点的请求（见上文网络请求声明）。
* **用途——限定工作目录的操作**：其余全部功能（构建小说状态树、列卷/列章、统计每章/全书字数、把大纲 / 世界观 / 人物 / 场景等文档载入写作提示词、对话面板的工具调用、敏感词确定性扫描、打字统计）都只在**你首次使用时自选的工作文件夹**（`work_dir`）及其 `SKILLS/` 目录内进行，该目录之外的文件从不被这些功能打开或扫描。对话面板的工具调用（模型请求读章节 / 执行写作命令）由你在聊天里发起的那一轮对话触发，属本地执行，且只作用于 `work_dir` 内的当前小说。
* **隐私保证**：所有遍历完全在你本机本地内存中进行。文件路径与内容仅在设备内处理，**绝不**上传、远程索引、泄露或共享给任何外部服务器——唯一例外是你自己主动触发的、上文已披露的 LLM 请求。
* **给审核者的摘要**：全库列举只发生在两个 UI 选择器且只暴露**路径**（文件夹选择器甚至限死 3 层 / 500 条目）；其余全部文件访问都留在用户自选的工作目录内，全程本地内存处理；除你主动发往自建端点的 LLM 请求外，没有任何东西离开本机。

## 概述

ArticleWriter 把你的 vault 变成 AI 辅助的小说创作工坊。每部小说是一个纯 Markdown 文件夹（YAML frontmatter 状态文档 + `案头资料/` 资料区 + `书稿/` 正文区按卷与章节组织），在此之上是完整的创作流水线：**一句话设定 → 全自动写书六阶段**（世界观 → 策划指南 → 时间线 → 书级大纲 → 卷大纲 → 章节），也可以单条命令只跑其中任何一步——创作 / 续写 / 重写 / 润色章节、去 AI 味、错别字检测、敏感词检测、全局视角审阅、从成稿正文反向分析人物与场景。

**技能系统**（`SKILLS/` 目录下的 Markdown，内置 29 个随启动播种）为各写作阶段供给技法要点、题材写法、禁用词清单与阶段身份提示词，全部是你可直接编辑的普通文件。**五个常驻可停靠面板**——写字台、LLM 对话（带工具调用：模型能读你的章节、代跑写作命令）、人物关系网、时间线、场景画布——让书的结构一键可达。全部数据留在本地；除你自行配置的 OpenAI 兼容模型端点外不需要任何外部服务。**桌面与移动双端**均可完整使用（手机端面板同样常驻，鼠标专属手势自动降级）。

> **注意（v0.3.5+）：** 旧三层 `WRITING_GUIDE.md` 创作规范体系**已废弃**——相关文件与 5 条命令已删除，存量文件在插件启动时自动清理。其功能由技能系统（题材/技法技能、禁用词清单技能、章节写作指导）与《故事状态.md》的 `word_range` 字段（命令「设置本章字数区间」）承接。

│   ├── 题材/<题材名>.md         # 题材技能（按书的 genre 自动加载）
│   ├── 编写类型/<类型名>.md     # 编写类型技能（按书的 writing_style 自动加载）
│   ├── 系统提示词/<名>.md       # system 提示词覆盖（内部机制、自动生效）
│   └── <技法技能>.md           # 技法技能，按阶段 opt-in
└── <小说名>/
    ├── 故事状态.md              # YAML frontmatter 存运行态（标题/类型/word_range/prev_chapters/
    │                           #   auto_book 全自动建书配置/book_skills 阶段技能/各章元数据）；旧 story_state.json 自动迁移并备份到 _backup/
    ├── 案头资料/                # 九件默认资料（大纲/策划指南/世界观/伏笔/笔记/人物/人物关系/场景/时间线）+ 用户自建文件
    │   ├── 灵感/灵感.md         # 灵感工具包（一条灵感一个 ## 块）
    │   ├── 码字记录.md          # 打字统计（自动按段追加）
    │   ├── 敏感词报告.md        # 全书敏感词汇总报告（按时间戳追加）
    │   ├── AI会话/              # 对话面板会话记录（自动保存）
    │   └── Skill/<技能名>.md    # 书籍级技能
    ├── 书稿/
    │   ├── 引言/                # 引言文档（自动播种的保留文件夹）
    │   ├── <卷名>/              # 卷实体目录（章节挂在卷下）
    │   │   ├── 文档/            # 卷级文档（卷大纲/人物/场景/时间线…，裸基名）
    │   │   └── 卷摘要.md        # 卷摘要（LLM，由该卷章摘要整体重建）
    │   └── 第NN章-<标题>/       # 每章一个文件夹（未归卷章节直接在 书稿/ 直属）
    │       ├── NN-<标题>.md             # 正文
    │       ├── NN-<标题>-大纲.md         # 章节大纲
    │       ├── NN-<标题>-摘要.md         # 章节摘要（延迟生成）
    │       ├── NN-<标题>-人物.md / -人物关系.md / -场景.md / -信息.md / -时间线.md

缺失文档在建书/建卷/建章时自动按「HTML 注释示例」模板播种；已存在一律跳过、不覆盖用户内容。文件名统一经 `safeFilename()` 清理。旧物理结构（资料文件散在书根、裸名 `章节.md`、旧前缀如 `初见-章节.md`）会被自动探测并收口迁移为 `案头资料/` + `书稿/` 结构；切书时也会提示批量改名旧格式文档。

## 技能系统（SKILLS）

技能是存放在 `<work_dir>/SKILLS/` 的写作技巧短文档（平铺一层、你在 Obsidian 里可直接编辑的普通 .md）。内置技能启动时**仅缺失才播种、绝不覆盖你的修改**，共 29 个（技法类 / 题材类 / 身份加强类）。技能注入**严格 opt-in**：五个写作阶段（世界观生成／策划方案生成／书籍大纲和卷级大纲生成／文章大纲生成／编写文章）在设置页各有一份引用文档清单，`skill:<技能名>` 条目决定哪个技能进哪个阶段的提示词；内置默认清单已含张力工具箱、各阶段身份加强技能、网文高频禁用词清单与世界观生成框架。

* **题材 / 编写类型技能**（`SKILLS/题材/`、`SKILLS/编写类型/`）按当前书的 genre / writing_style **自动加载**；「创建新小说」「修改小说信息」的下拉选项就由这两个目录生成。
* **字数占位符**：技能文本里可写 `{{word_low}}` / `{{word_high}}` / `{{word_range}}`，装配提示词时按该书《故事状态.md》的 `word_range` 插值。
* **书籍级技能**：同格式，存 `<书>/案头资料/Skill/`，用命令「书籍 Skill 阶段配置…」按阶段选用，注入排在系统技能之后；编辑/删除＝直接操作对应文件。
* **系统提示词覆盖**（`SKILLS/系统提示词/`）：覆盖 7 处内部 system 提示词（人物场景分析/章摘要/卷摘要/卷大纲生成/章大纲编写/时间线生成/错别字检测），自动生效、不进 opt-in 清单。
* 命令：**新建 Skill…**（创建，可选系统级/书籍级）、**书籍 Skill 阶段配置…**（按阶段多选）。

## 常驻面板

* **写字台**（书本图标；移动端在左栏抽屉）：工作目录、小说列表（点击切书）、当前书信息、**「小说状态 / 码字状态」Tab 区**、案头资料与书稿树（卷→章、引言、展开折叠、行右键菜单覆盖新建/删除/改名/生成/导出）、Skill 子节点、刷新。在编辑器打开某章正文也会自动激活该章。
* **LLM 对话**（消息图标）：多轮流式聊天、顶部下拉切换模型配置、@引用 vault 任意文档、自然提及章节/卷/文档自动加载进上下文。会话**自动保存到《案头资料/AI会话/》**、重开自动接回；「压缩上下文」＋按模型窗口自动压缩保证长会话可用。**工具调用**：模型可在对话轮内读章节/大纲/文档、检索 vault、设置当前章、把内容存成文件，乃至直接代跑写作与生成命令（write/续写/重写/润色/去AI味/审阅、世界观/大纲/时间线生成、连续编写）——全部在本地对当前小说执行，结果回灌给模型继续对话。对话引用文档/技能在设置页 opt-in，与写作阶段同一套选择器。
* **人物关系面板**：汇总书/卷/章三层《人物关系.md》。**卡片模式**＝按层级分组的关系卡（角色对＋类型徽章＋状态点＋描述），面板内直接增删改。**图表模式**＝力导向关系网（主角居中、按关系数分级）、弧线连线、颜色＝类型、线型＝状态、加粗＝多处登记；`Ctrl/Shift`＋滚轮以鼠标为不动点缩放、按住拖动平移、双击/右键＝适应全图、图例行可折叠；点节点＝下方「人物状态」抽屉展示其《人物.md》设定（每来源文档一条折叠项），多处登记时可一键「合并」。文档改动自动刷新。
* **时间线面板**：把三层《时间线.md》合并成一条按时间点数值升序（支持 `-129-06-15`）的纵向时间轴，带来源层级标签与权重，子事件挂父事件带轨道；面板内完整编辑——增/删/改（弹窗）/完成切换/**拖时间徽章改时间点**（桌面按住 Ctrl/⌘ 再拖、移动端长按「抓住」后下一手势拖）、`Ctrl+Z` 撤销、筛选、跳来源文档；合并时间线作为【时间线】注入写作提示词。
* **场景面板**：三层《场景.md》卡片画布——可缩放平移、拖动卡片摆位并落盘（`- 位置：x,y`）、大小场景父子连线、按地形淡染、面板内增删改。

## 工作流程（work_dir）

1. **首次使用**任何 ArticleWriter 命令时自动弹出**工作目录选择器**——从 vault 内已有文件夹中选定写小说的文件夹作为 `work_dir`。确定后该目录自动多一份带版本戳的《使用说明.md》（内置手册，附作者联系方式二维码图片；插件升级后自动重建，平时不覆盖你的修改），`SKILLS/` 内置技能同时播种。
2. 以后**创建小说、创建章节、打开文档、切换章节、字数统计等全部在 work_dir 下操作**；每部小说是 work_dir 下的一个子文件夹，技能在 `work_dir/SKILLS/` 跨书共享。
3. 换目录用「选择工作目录」命令或设置页「重新选择…」（切换后清空旧小说记忆）。
4. 多本书时各命令会弹小说选择器并记住上次选择。

## 设置（Obsidian 设置 → ArticleWriter）

* **工作目录（work_dir）**：首次使用时自动弹出选择器初始化，可手动重选。
* **LLM 配置**：命名的模型配置组（OpenAI 兼容），存于插件数据目录 `.obsidian/plugins/articlewriter/data.json`；首启预置 local / deepseek / qwen-dashscope 三组模板待填 api_key/模型名。全局有一个激活配置；**「写作阶段模型配置」五个 tab** 可为每个写作阶段单独指定配置。
* **各阶段引用文档清单**：决定每个阶段注入什么——内置文档、任意 vault 文件、任意技能（「添加技能…」）；拖拽排序、恢复默认。对话面板同理（「对话窗口引用文档/技能」）。
* **码字记录段长**（默认 10 分钟）、**前文注入是否含卷摘要**（默认关）、**创建后自动打开文档**（建书开《大纲.md》、建章开正文）。多数书级参数（`word_range`、`prev_chapters`、`include_volume_summary`、`auto_book`、`book_skills`）写在《故事状态.md》frontmatter 里按书覆盖全局设置，显式设置优先。

## 构建与安装

```bash
npm install
npm run build        # 产物 main.js + manifest.json + styles.css 输出到 release/
```

开发模式（watch）：`npm run dev`。测试：`npm test`；发布门禁 lint：`npm run lint`。

手动安装：把 `release/`（或 GitHub Release）里的 `main.js`、`manifest.json`、`styles.css` 复制到 `<你的vault>/.obsidian/plugins/articlewriter/`，在 Obsidian「设置 → 第三方插件」中启用；更新插件后需重载生效。
