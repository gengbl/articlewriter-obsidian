# L2 · 写作指南（创作规范三层）

## 模块概要

负责创作规范三层文件（小说级 > 用户级 > 系统级）、四个「类型要点」文件（插件数据目录 guide-types/*.md，按书籍题材命中组装）与各书《写作指南汇总.md》聚合文件：各层查看/编辑、「生成写作指南」投放空模板、「重新生成系统写作指南」覆盖重置（含类型文件）、汇总持久化与变更检测。LLM 写作命令、对话与 **v0.2.x+ 大纲生成/AI 拆章**注入的【创作规范】**唯一来源**是该书聚合文件（去注释正文；这些入口经 `loadWriterGuides` 触发其检测更新重建，批量循环整批只查一次）。

## 行为约定

- **优先级降序**：①小说级 `<书名>/WRITING_GUIDE.md` > ②用户级 `<work_dir>/WRITING_GUIDE.md` > ③系统级插件数据目录文件 `.obsidian/plugins/articlewriter/WRITING_GUIDE.md`——系统级路径**固定、非用户可配**（原 `llm.system_guide_path` 设置项已移除，data.json 的 `system_guide` 仅作一次性迁移种子）。
- **聚合文件 = 三层按类目合并落盘**（serializeAggregateGuide + agg-hash md5 变更检测头），仅当三层任一 md5 变化才重算；任一层变更后刷新该书汇总。
- **空指示段自动注释**（commentOutEmptySections）：空小节整体包进 HTML 注释并加引导提示；注入前 stripComments 剥全部注释，这些段落不参与提示词生成（不破坏 agg-hash 幂等）。
- **「通顺与逻辑」是指南总兜底（v0.2.12+）**：系统指南一·核心创作哲学首条明示「通顺与逻辑优先于一切风格技巧」——所有去AI味手法（毛刺/留白/跳笔/不完美）不得以语病、因果断裂、信息缺失为代价；原损害通顺逻辑的条款已逐个划定边界（九C「次序以清楚为先」「允许没说完不允许说不通」「保留不完美＝保留棱角非病句」、九D「留白不写≠写得不合逻辑」、六.1 删对话以信息不断链为界、七.7 碰壁须有缘由）。`prompts.ts` 三个写作 prompt 均带同义兜底条目（buildChapterPrompt 第12条／buildContinuePrompt 第9条／buildRewritePrompt「通顺与逻辑优先」条）；章末收束约定两头对齐——指南十二节「禁止刻意堆砌结尾悬念」与 prompt 第4条（自然终点收束＋有大纲「章末钩子」才落钩子）不再互相矛盾。**注意**：已播种到插件数据目录的系统级指南不会自动更新，需走「重新生成系统写作指南」或手动改文件。
- **去AI味条款不用精确数字定额（v0.2.12+）**：次数/比例一律定性表述（「删至少30%对话」→「大幅删减」、「每章3-5个一句话段落」→「穿插若干个」、「反复≥3次」→「反复出现」、「成语≤5%」→「占比极低」、「分三次给」→「分好多次给」，共 17 处；自检清单同行同步）——精确配额本身就是机械感来源，模型会为凑数写注水内容。功能性数字不在此列：字数配置标记、十一·格式要求的「段落3-5行」、提示词动态字数区间、列表编号均保留。
- **中文语序硬性要求（v0.2.12+）**：二·基本风格第6条「中文语序（硬性要求，句子与对话都适用）」——主谓宾直陈（禁超长定语一口气前置）、动词要有动作（删「进行了激烈的战斗」类形式动词/名词化、少「被」字句）、删欧化框架（「当……的时候」「在……的情况下」「对于……而言」「通过……的方式」及「其中/以及」）、对话按口语语序（短句/省略主语/倒装/语气词居尾，禁「请允许我」「我感到十分荣幸」类翻译腔敬语感叹，情绪越高句子越短）；检查标准＝默读像译制片台词或英译汉说明书即翻译腔。六·对话写作第9条「口语语序」同向（原第9条顺延第10条）、十三节自检清单第31行。与 `prompts.ts` `DESC_STYLE_GUIDE_COMPLETE`（仅 desc_style=complete 时注入、管「别把一句话拆碎」）方向互补不冲突。
- **白描是唯一描写方式、禁解释性描写（v0.2.12+）**：三·场景描写第2条「白描，不解释」为总规则——只写看得见/听得见/摸得着的事实，禁点破行为含义（「他在强压怒火」）、禁替景物解释情绪的比喻（「雨仿佛在为他哭泣」）、禁「显然/可想而知/换句话说」式解读、禁主观定性渲染（「凄美」「悲壮」）；检查标准＝删掉解释性句子后意思反而更清楚则本该删。十二节「禁止解释性描写」红线＋十三节自检清单第30行同向约束；四·环境即心境同步改为「基调靠景物事实承载，不是靠解释句点明」。三节原2-5条顺延为3-6条（全文交叉引用均为名称引用，无编号依赖）。
- **禁用词注入去重（v0.2.12+）**：最终 system prompt 曾把禁用词内容注入 3 遍（代码内置块 804＋「指南补充」1619＋【创作规范】里的第十节 1596≈4019 字符、84 条中 82 条出现≥3 次）——根因是 `BANNED_TOKEN_RE` 闭合字符类误写 `»`(U+00BB) 应为 `」`(U+300D)，致 `buildMergedBannedBlock` 对代码块提取 0 token、「指南纯列表行过滤」全程失效。已修复正则；并简化指南第十节（删与代码变体表完全重复的两行清单、句式改写规则移至九E 只注入一次、备注行改 HTML 注释）、`buildBannedWordsBlock` 变体表跳过组内已列精确词（纯展示层）。简化后：system prompt 14110→12040 字符，「指南补充」1619→121，残留 2× 为设计使然（代码块机器强制＋指南核心清单人类可编辑，后者经过滤不再进「指南补充」）；AI腔句式组补「不对劲」闭合检测缺口。
- **禁用词表词条增补**：banned_words.ts 词表新增词条时须同步根 WRITING_GUIDE.md 第十节对应分类行（两边一致后该行在合并时被「纯列表行过滤」整体跳过、不重复注入）；用户级空模板（docs/WRITING_GUIDE_template.md）只含章节标题不罗列词条、无需跟随。已增补实例：情绪模板词组「指节发白」（AI 高频情绪物理化套话——紧张/愤怒/隐忍）＋变体规则 `指节.{0,4}(?:发白|泛白)`（拦「指节泛白」「指节都发白」等绕开写法）；同族四词「胸膛剧烈起伏 / 嘴唇抿成一条线 / 指甲掐进掌心 / 青筋暴起」各配精确词＋变体规则（`(?:胸膛|胸口).{0,4}(?:剧烈|猛烈|大幅)起伏`、`(?:嘴唇|唇).{0,4}抿成.{0,4}(?:一条)?(?:直)?线`、`指甲.{0,4}(?:掐|嵌|抠)进.{0,4}(?:掌心|掌纹|肉)`、`青筋.{0,4}(?:暴起|暴跳|直跳)`）。**收窄原则**：只禁套话形态、避开合法用法——「胸口再无起伏」（死亡）、「胸口微微起伏」（平静呼吸）不拦；「青筋凸起/鼓起」在书稿中是人物体征细节（壮汉胳膊、病中手背）故不入变体规则，仅禁「青筋暴起/暴跳/直跳」的愤怒套话；「指甲缝里嵌进去一层灰」（人物细节）、「指甲抠进木头里」（物理动作）因宾语不在 掌心/掌纹/肉 之列而天然放行。**纯变体规则实例**（无精确词、不进第十节清单行，改在九C 加生成端要求「模糊整数量词」）：「三天/三次/三层（模糊整数量词）」变体规则 `(?:^|[^第两])三(?:天|夜|日|次|遍|下|口|声|圈|层|步|秒|回|趟|阵)`——AI 用「三+量词」填充动作/周期描写；收窄：前缀 `(?:^|[^第两])` 排除序数「第三次/第三天」与约数「两三秒」（文件头约定禁用 lookbehind），量词表不含 十/百/千，「三十岁」「三百块」等基数不受影响。注意：存量书稿中「三X」多为精确情节细节（如「看了三次手机。第一次两点十七…」），检测会误伤——用户已确认接受该代价（检测＋生成约束两者都要）。
- **张力设计工具箱并入系统指南（v0.2.x+）**：用户提供的八类张力手法（赌注升级/时间压力/盟友变数/两难选择/悬念反转/章末钩子/节奏控制/反派塑造＋用法建议）整理为系统指南新节「## 八、张力设计工具箱」（子节 A–H），原八～十三节顺延为九～十四节，全文交叉引用同步重编号。去重决策：①节奏控制第1条（三章一小紧/十章一大紧/每三四章一章低张力日常）并入七·2「节奏张弛」扩写，新节 G 只保留两个具体落点并指向七·2；②删九D「加入意外转折」行，其独有措辞（"大纲中的叙事是简洁的，真正的故事是曲折的"）折入八E 开头并加「不偏离大纲确定的走向（见五·事件展开）」限定；③八F 章末钩子开头加对齐注——仅当本章大纲给出「章末钩子」或情节自然产生钩子时才用这些手法，否则按七·4 自然收束（与十二·禁止刻意堆砌结尾悬念一致）；④一·好故事三要素后加指针句「情节如何让人好奇，见八·张力设计工具箱。」；⑤自检清单追加 #32（赌注落到具体的人/时限读者看得见）、#33（反派晚露面、逻辑让读者觉得有道理）。用法建议放新节开头：挑五到八条作全书贯穿规则、其余按章节轮换，一切手法让位于人物逻辑与因果链（见七·严密因果链、十二·禁止降智）。**2026-11-08 整合去重**：删「八G·节奏控制」节——其两个具体落点（高潮前让主角失去最重要的东西／最低点发生在最自信的时候）折入七·2「节奏张弛」；原「八H·反派塑造」重编号为八G（唯一外部引用自检 #33 同步改指）。结尾规则以七·4 为单一事实源（默认自然收束；仅当大纲给出「章末钩子」或情节自然产生钩子才用钩子手法），八F 开头与十二·禁止刻意堆砌结尾悬念均压缩为指向七·4 的指针。九A 删纯指针条目 2/3/5（余下重编号 1–3，无外部引用）。八节开头用法建议压缩＋补一句心法（张力靠信息差与具体赌注——让读者比主角多知道一点，让赌注落在具体的人身上）。A–E 内容与自检 #32/#33 不变。实测（真实管线 mergeGuideCategories→serializeAggregateGuide→stripComments→trim，同 persistAggregatedGuide 口径）：注入的【创作规范】guideText 15020→14777 字符（−243、−1.6%），禁用词类目两侧均 455 不变；29 条手法全部保留、交叉引用全部可解析。docs/WRITING_GUIDE_template.md 已用 buildEmptyGuideTemplate 重生成（唯一变化为 G/H 标题并 G）。
- **类型要点拆分为独立文件、按题材组装（v0.2.x+）**：原系统指南「## 十一、不同类型写作要点」（玄幻仙侠/都市现实/科幻/历史武侠四子节）拆为 4 个独立文件——唯一来源 docs/guide-types/*.md（esbuild `.md=text` 打包），首启播种到插件数据目录 `.obsidian/plugins/articlewriter/guide-types/<key>.md`（用户可编辑定制；已存在不覆盖）。「重新生成系统写作指南」一并覆盖重置这 4 个文件。汇总管线 `persistAggregatedGuide(story, bookText, userText, systemText, genre)` 按故事状态 `genre` 自由文本经 `matchGuideTypes`（src/guide_types_default.ts GUIDE_TYPES 关键词正则）匹配，命中的每个类型以「## 写作要点（<name>）」追加进合并结果「通用」类目（多命中依次追加；未命中→不注入）；agg-hash 头新增 `t=` 字段 = md5(类型要点拼接文本)（无命中为空串），旧汇总头无 t → parseAggHash 按 "" 处理 → 一次性重建。**迁移注意**：已播种的旧系统级指南仍含完整第十一节（会作为「通用」继续注入、与新组装的类型要点重复），不做自动剥离——升级用户需跑一次「重新生成系统写作指南」消除重复（本地 vault 部署时手动覆盖播种的系统指南）。对话面板「无当前小说」分支无题材上下文，保持 user+system 两层合并、不落盘、不注入类型要点。根指南删第十一节后十二/十三/十四重编号为十一/十二/十三（全文交叉引用同步）。
- **系统指南开头「作者身份强化」节（v0.2.x+）**：根 WRITING_GUIDE.md 正文开头（字数配置行后、「一、核心创作哲学」前）新增**不带编号**的引言节「## 作者身份（每次生成前生效）」——声明模型是成熟的中国网络文学作家而非"文本生成器"，列六项应具备并正在运用的能力（叙事掌控/人物思维/细节观察力/节奏感/读者意识/自我批判），末句点明"以下所有规范都建立在这个身份之上"。不编号是为避免一~十三重排破坏「见八·张力设计工具箱」「九B」「十二」等交叉引用。**提示词真实落位**：该节属「通用」类目，三层合并按层序逐行去重（书级行→用户级行→系统级行），有书级/用户级指南的书其身份文本排在它们通用内容之后；【创作规范】块整体经 `assembleSystemPrompt` 附在系统消息末尾，并非整个提示词字面最前。docs/WRITING_GUIDE_template.md 已用 buildEmptyGuideTemplate 重生成（骨架含新段名；书级/用户级指南该节留空时 commentOutEmptySections 注释掉不参与提示词，填写则按本层优先级参与合并）。
- **改动根 WRITING_GUIDE.md 段落结构后须用 prompts.ts `buildEmptyGuideTemplate` 重生成 `docs/WRITING_GUIDE_template.md`**（空模板再导出层，「生成写作指南」投放用）。
- 使用说明《使用说明.md》（work_dir 根）由 seedUsageDoc 在设置/切换工作目录后自动投放（仅缺失或为空写入），手动重建走 `cmdGenerateUsageDoc()`。
