# L2 · 写作指南（创作规范三层）

## 模块概要

负责创作规范三层文件（小说级 > 用户级 > 系统级）与各书《写作指南汇总.md》聚合文件：各层查看/编辑、「生成写作指南」投放空模板、「重新生成系统写作指南」覆盖重置、汇总持久化与变更检测。LLM 写作命令与对话注入的【创作规范】**唯一来源**是该书聚合文件（去注释正文）。

## 行为约定

- **优先级降序**：①小说级 `<书名>/WRITING_GUIDE.md` > ②用户级 `<work_dir>/WRITING_GUIDE.md` > ③系统级插件数据目录文件 `.obsidian/plugins/articlewriter/WRITING_GUIDE.md`——系统级路径**固定、非用户可配**（原 `llm.system_guide_path` 设置项已移除，data.json 的 `system_guide` 仅作一次性迁移种子）。
- **聚合文件 = 三层按类目合并落盘**（serializeAggregateGuide + agg-hash md5 变更检测头），仅当三层任一 md5 变化才重算；任一层变更后刷新该书汇总。
- **空指示段自动注释**（commentOutEmptySections）：空小节整体包进 HTML 注释并加引导提示；注入前 stripComments 剥全部注释，这些段落不参与提示词生成（不破坏 agg-hash 幂等）。
- **「通顺与逻辑」是指南总兜底（v0.2.12+）**：系统指南一·核心创作哲学首条明示「通顺与逻辑优先于一切风格技巧」——所有去AI味手法（毛刺/留白/跳笔/不完美）不得以语病、因果断裂、信息缺失为代价；原损害通顺逻辑的条款已逐个划定边界（八C「次序以清楚为先」「允许没说完不允许说不通」「保留不完美＝保留棱角非病句」、八D「留白不写≠写得不合逻辑」、六.1 删对话以信息不断链为界、七.7 碰壁须有缘由）。`prompts.ts` 三个写作 prompt 均带同义兜底条目（buildChapterPrompt 第12条／buildContinuePrompt 第9条／buildRewritePrompt「通顺与逻辑优先」条）；章末收束约定两头对齐——指南十二节「禁止刻意堆砌结尾悬念」与 prompt 第4条（自然终点收束＋有大纲「章末钩子」才落钩子）不再互相矛盾。**注意**：已播种到插件数据目录的系统级指南不会自动更新，需走「重新生成系统写作指南」或手动改文件。
- **去AI味条款不用精确数字定额（v0.2.12+）**：次数/比例一律定性表述（「删至少30%对话」→「大幅删减」、「每章3-5个一句话段落」→「穿插若干个」、「反复≥3次」→「反复出现」、「成语≤5%」→「占比极低」、「分三次给」→「分好多次给」，共 17 处；自检清单同行同步）——精确配额本身就是机械感来源，模型会为凑数写注水内容。功能性数字不在此列：字数配置标记、十一·格式要求的「段落3-5行」、提示词动态字数区间、列表编号均保留。
- **中文语序硬性要求（v0.2.12+）**：二·基本风格第6条「中文语序（硬性要求，句子与对话都适用）」——主谓宾直陈（禁超长定语一口气前置）、动词要有动作（删「进行了激烈的战斗」类形式动词/名词化、少「被」字句）、删欧化框架（「当……的时候」「在……的情况下」「对于……而言」「通过……的方式」及「其中/以及」）、对话按口语语序（短句/省略主语/倒装/语气词居尾，禁「请允许我」「我感到十分荣幸」类翻译腔敬语感叹，情绪越高句子越短）；检查标准＝默读像译制片台词或英译汉说明书即翻译腔。六·对话写作第9条「口语语序」同向（原第9条顺延第10条）、十三节自检清单第31行。与 `prompts.ts` `DESC_STYLE_GUIDE_COMPLETE`（仅 desc_style=complete 时注入、管「别把一句话拆碎」）方向互补不冲突。
- **白描是唯一描写方式、禁解释性描写（v0.2.12+）**：三·场景描写第2条「白描，不解释」为总规则——只写看得见/听得见/摸得着的事实，禁点破行为含义（「他在强压怒火」）、禁替景物解释情绪的比喻（「雨仿佛在为他哭泣」）、禁「显然/可想而知/换句话说」式解读、禁主观定性渲染（「凄美」「悲壮」）；检查标准＝删掉解释性句子后意思反而更清楚则本该删。十二节「禁止解释性描写」红线＋十三节自检清单第30行同向约束；四·环境即心境同步改为「基调靠景物事实承载，不是靠解释句点明」。三节原2-5条顺延为3-6条（全文交叉引用均为名称引用，无编号依赖）。
- **禁用词注入去重（v0.2.12+）**：最终 system prompt 曾把禁用词内容注入 3 遍（代码内置块 804＋「指南补充」1619＋【创作规范】里的第九节 1596≈4019 字符、84 条中 82 条出现≥3 次）——根因是 `BANNED_TOKEN_RE` 闭合字符类误写 `»`(U+00BB) 应为 `」`(U+300D)，致 `buildMergedBannedBlock` 对代码块提取 0 token、「指南纯列表行过滤」全程失效。已修复正则；并简化指南第九节（删与代码变体表完全重复的两行清单、句式改写规则移至八E 只注入一次、备注行改 HTML 注释）、`buildBannedWordsBlock` 变体表跳过组内已列精确词（纯展示层）。简化后：system prompt 14110→12040 字符，「指南补充」1619→121，残留 2× 为设计使然（代码块机器强制＋指南核心清单人类可编辑，后者经过滤不再进「指南补充」）；AI腔句式组补「不对劲」闭合检测缺口。
- **禁用词表词条增补**：banned_words.ts 词表新增词条时须同步根 WRITING_GUIDE.md 第九节对应分类行（两边一致后该行在合并时被「纯列表行过滤」整体跳过、不重复注入）；用户级空模板（docs/WRITING_GUIDE_template.md）只含章节标题不罗列词条、无需跟随。已增补实例：情绪模板词组「指节发白」（AI 高频情绪物理化套话——紧张/愤怒/隐忍）＋变体规则 `指节.{0,4}(?:发白|泛白)`（拦「指节泛白」「指节都发白」等绕开写法）。
- **改动根 WRITING_GUIDE.md 段落结构后须用 prompts.ts `buildEmptyGuideTemplate` 重生成 `docs/WRITING_GUIDE_template.md`**（空模板再导出层，「生成写作指南」投放用）。
- 使用说明《使用说明.md》（work_dir 根）由 seedUsageDoc 在设置/切换工作目录后自动投放（仅缺失或为空写入），手动重建走 `cmdGenerateUsageDoc()`。
