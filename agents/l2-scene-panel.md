# L2 · 场景面板

## 模块概要

自定义面板「场景」（view type `articlewriter-scenes`，命令 `scene-panel`＋ribbon `map`）：把当前小说**书级《案头资料/场景.md》/ 卷《文档/场景.md》/ 章节目录《场景.md》三层**的场景条目汇总成**卡片画布**展示，支持拖动摆放位置（位置落盘回《场景.md》）、面板内增删改场景、大场景包含小场景（父子）。

## 行为约定（按实现批次）

- **卡片展示（步骤 1，已实现）**：主体区每张卡片＝场景名（`title` 字段优先、回落 `## <scene_id>` 标题名）＋场景 id（与显示名不同时才显示）＋来源层级标签（书籍级／卷 · X／章 · 第N章 Y）＋父场景标注（`⊂ 父名`；父 id 找不到时注明「未找到父场景」）＋描述＋角色 chips＋备注行。**v0.4.9+ 有可见子场景的父场景卡片＝「区域头」**：照样写场景名与描述，只额外挂虚线边框（`.aw-scene-card.is-region`）＋头部「N 个子场景」小标，并且这张卡片会被锚定到其包含框的左上角（见「大小场景」段）。头部＝筛选框（场景名/标题/描述/备注/角色/父场景全字段匹配）＋刷新按钮；汇总行「共 N 条：书籍级 X · 卷级 Y · 章级 Z」（筛选时「匹配 X 条（共 Y 条）」）。**双击卡片**打开**场景编辑弹窗**（v0.4.8+ 用户要求；来源文档入口＝右键「打开来源文档」）。卡片顺序＝文档枚举序（书级 → 各卷 → 各章）。三层《场景.md》改动由 vault 事件防抖自动刷新（同人物关系/时间线面板）。空态按「未设工作目录 / 目录下无小说 / 未选当前小说 / 无场景（给写法教学）」分级引导。

- **大小场景（步骤 5，已实现）**：`- 父场景：<id>` 表达包含。编辑弹窗「父场景」下拉候选＝全部场景去重（显示名口径），**排除自身＋全部后代**（沿父链闭包展开，防父子成环）；选「（无 · 顶层场景）」＝删除该行。卡片右键「添加子场景」＝新建弹窗预填该父、写回**与父同一文档**。画布上**父子之间不再画线（v0.4.9+ 用户要求）**——层级关系由**包含框**表达，而「大场景的名字在区域左上角」**靠把父场景卡片本身摆到区域左上角实现（不是在外面挂一份浮动文字）：有可见子场景的父场景卡片＝「区域头」`.aw-scene-card.is-region`（虚线边框＋头部「N 个子场景」小标 `.aw-scene-kids`），**名字与详情仍写在卡片里**（用户明确要求＝不要单独挂在框外的空白处）；渲染时 pass2.5 后序归位＋拖动中的 `applyRegions` 走**同一条顺序**（v0.4.9+ 用户要求＝**顺序不能反**）：① 先按**全部子场景**当前的包围盒算出区域骨架（**不含父卡片的位置**）⇒ ② 由它反推**父卡片的新位置**（`scene_geometry.regionHeadFor`＝与最左子场景对齐、整块排在最上子场景上方 `SCENE_CHILD_GAP` 处）⇒ ③ 区域矩形＝`frameBoxFor(子场景们 ＋ 派生后的区域头)`。⇒ **有子场景＝父卡片的位置是纯派生的**（`- 位置：` 里存的值只当缺省，它旧摆在哪儿绝不参与区域计算），拖动任一子场景＝区域当场按子场景长/缩，**随后**父卡片被搬到新的区域左上角（＝用户要求的「先把子场景算完区域，再算父卡片的新位置」）；`regionFor`/`regionHeadFor` 均为纯函数＋单测（＝区域头恒在框内、左/右/下三边恒由子场景决定、平移全部子场景＝区域与区域头同步平移＝拖整组不会被弹回）；拖动收尾写回的是**重算后的坐标**（＝屏幕上看到的就是落盘的值）；**v0.4.9+ 用户要求＝被区域口径顺带搬走的大场景卡片（区域头）也一并写回它自己的 `- 位置：`**（按下拖动时先记下各区域头此刻的坐标＝`headStart`，收尾只把「本次真的被挪过」的头卡片追加进写回清单；从没写过位置的由 `rewriteScenePosition` 在场景块尾新增该行；一层层嵌套的区域逐层各自写回，本次没被挪动的大场景不动它的行）；自动布局的子卡片间距 `SCENE_CHILD_GAP`(24) 已含框外扩 FRAME_PAD 的净空、顶层起点也先让出 FRAME_PAD＝包含框不会被卡片压住/顶出内容上边界；「适应全图」的包围盒**并入各包含框矩形**＝框边不会被切在画面外；筛选后两端都可见才有框；**区域的大小从不写死＝每次都按「该大场景的**全部子场景**」当前的包围盒现算**（`scene_geometry.frameBoxFor`/`regionFor` 纯函数＋单测＝**父卡片的旧坐标不参与**）：**拖动任一子场景（尤其往下挪）＝该区域的高/宽当场跟着长或缩**（子场景上移则区域跟着缩，不留旧尺寸）**并把该区域的父卡片一并搬到新的区域左上角**，并且**画布的内容范围（可滚/可平移的范围）同步撑开**＝区域长出来那一截既看得见也滚得到（v0.4.9+ 修的用户反馈：子场景下移后「区域高度没变化」＝长出来的部分被旧内容边界切掉了）；松手落盘后整图刷新校准；父 id 在快照里找不到时卡片标注「未找到父场景」）。**只连真有 `- 父场景：` 关系的场景**：父解析＝**同一文档优先**→全局文档序首个（跨文档同名不误连），再走父链防环（成环者断链按顶层渲染、不连线不成组）。有可见子场景的父场景另有**包含框**＝该大场景的**有效区域**（圆角虚线矩形衬在卡片下层，框＝**全部子场景**的包围盒（再并入已按区域反推出位置的父卡片那一行）＋外扩 FRAME_PAD＝左/右/下三边恒由子场景决定、只有顶边为区域头让出一行；拖动任一成员一律把所有区域重算一遍（`applyRegions`＝最深一层先归位，嵌套区域才不会各算各的），包含关系视觉始终成立）。**包含框是纯衬底（v0.4.7+）**：不拦截指针——**任何空白（含框内）按住拖动＝画布平移视野**，不改任何坐标；整组挪动＝**拖任一卡片即整组移动**（不必非得点住框或父卡片）。自动布局下子场景天然排在父卡片内部下方（嵌套递归），用户可整组拖动散开。
