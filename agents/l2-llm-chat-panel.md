# L2 · LLM 对话面板

## 模块概要

- **LLM 对话窗是常驻 ItemView 不是 Modal**：`LlmChatView`（`src/llm_chat_view.ts`）经 main.ts `registerView(LlmChatView.VIEW_TYPE, ...)` 注册 + ribbon 图标；自持 history 与每轮 AbortController，配置经构造注入的 getter 实时取 settings.llm；**顶部「模型：」下拉切换即写回 data.json 的 `llm.chat_model`**（v0.2.22+，构造第 5 参 `setActiveModel` 由 main.ts 注入 `setActiveLlmFromChat`；对话框模型只影响对话框自身——写作命令/连接测试各按所属阶段映射取模型〔getPhaseLlmSetup〕、不受其影响；重启后对话框下拉按它加载），设置页改对话框模型或新建/删除/重命名配置后经 main.ts `syncChatModelSelect()` 反向同步下拉（`refreshModels` 已改为 public 且**一律以 `chat_model || active_llm` 为选中依据**）。可见时才抢焦点（offsetParent 判空），避免停靠他区打断编辑。`StatusView`（状态页）同款：数据 getter + 写动作回调注入，渲染陷阱一致（见 [l3-view-rendering.md](./l3-view-rendering.md)「常驻 ItemView 渲染陷阱」）。
- **v0.4.6+ 自然提及自动加载**：发送时除手动 @ 引用外，输入文本里的自然提及会被自动识别并把对应内容注入本轮上下文（识别纯模块 `src/chat_refs.ts`，读盘装配在 main.ts `collectChatAutoRefBlocks`，构造第 7 参注入）——识别形态：`第N章`（阿拉伯/中文数字）→该章正文、`第A到B章`（到/至，范围自动展开、单轮上限 10 章）→逐章正文、`第N卷`→该卷《卷大纲.md》、`《标题》`与「章节标题直接出现在句子里」→按章标题解析（解不到章回落内置文档名映射、再回落案头资料同名 .md）、关键词 故事状态/策划指南/人物关系/时间线/世界观/全书大纲/大纲→对应内置文档（「故事状态」注入格式化进度摘要而非原文件）。无需动词（「看/说说/评价/加载」皆可、不提动词也触发）；手动 @ token 先掩掉防重复加载；同章号跨卷歧义→当前卷优先再按卷 order；无当前小说/无命中/读盘失败＝静默跳过不阻断发送。生效表现：内容块追加进本轮 user 消息（与 @ 展开同款 `=== 标签 ===` 格式、计入自动压缩估算）、用户气泡下追加「〔自动加载：…〕」清单、状态行显示「自动加载 N 项」。
- **v0.4.6+ 工具调用（function calling）**：面板每轮请求带 `CHAT_TOOLS_PAYLOAD`（工具定义在纯模块 `src/chat_tools.ts`，共 21 个——只读：`read_chapter`/`read_doc`（世界观/大纲/人物关系/时间线/策划指南/故事状态）/`read_chapter_outline`/`read_volume_outline`/`list_chapters`/`search_vault`/`set_current_chapter`；写作命令代跑（`CHAT_WRITING_TOOLS`）：`review_chapter`/`continue_writing`/`rewrite_chapter`/`write_chapter`/`polish_chapter`/`deai_chapter`；书级生成命令代跑（`CHAT_GENERATION_TOOLS`）：`generate_worldview`/`generate_planning_guide`/`generate_timeline`/`generate_book_outline`/`generate_vol_outline`/`outline_to_chapters`/`write_chapters_consecutive`（`volume_name` 均经 `resolveToolVolId` 卷名→卷 id）；落盘：`save_content_to_file`（SaveReplyModal 人证：路径可编辑、覆盖勾选、取消不落盘，逐级建目录走共用 `modals.ensureParentFolders`））。模型返回 `tool_calls` → 面板经构造第 8 参转 main.ts `chatExecTool` 本地执行 → `role:"tool"` 结果续轮回灌，直到模型给出最终回答（上限 `MAX_TOOL_ROUNDS=5` 轮；工具结果统一截断 12000 字）。**写作命令工具走原命令同款流程**：代跑前预置 `chatToolCtx`（章节直给＝`targetChapterKey` 免弹窗、补充要求＝`prompt()` 一次性预答，instruction=null＝不预答任何弹窗如新建章标题输入）、当前章驱动型命令（续写/重写/编写/润色）先 `switchChapter` 切当前章（review/deai 走 targetChapterKey 不动指针），结果仍进「生成过程」面板由用户**保存/不保存**确认才落盘，产出文本回灌给模型继续推理（`peekGenPanelText`）。状态行显示「🔧 正在执行工具 name(参数)」。中间工具轮**不落会话历史**（只存档最终答案）；端点拒绝 tools 参数（不支持 function calling 的本地服务）→ 自动去参重试一次、按普通对话继续；执行失败以文本回灌不断流。**生成命令工具（`runChatGenerationTool`）**：模式/章数/覆盖确认/中断续跑三选等弹窗一律留给用户在聊天阻塞期间作答，仅 `generate_worldview` 的 premise 可由工具参数预答（复用 `chatToolCtx` instruction 接缝，该命令唯一 prompt）；命令直接写盘的（拆章/时间线）无流式产出时如实回灌「已结束但没有流式产出，请查看文档与通知」；`write_chapters_consecutive`（连续编写）逐章**免确认自动保存**，回灌不走面板文本、改用 `chapterFilledMap` 正文前后快照差集报告「本轮新写了哪几章（字数）/仍为空的章」。**防「行动宣告就停下」**：注入执行器时系统提示词追加【工具调用规则】块（必须本次回复内直接发起 tool_calls，不得只输出「我先看看…」类意图文字）；兜底：模型回了含「我先/让我/即将…」意图词但无 tool_calls 的短文本（≤300 字）时，循环自动催办一次（把宣告＋「请继续直接调用工具」的用户指令续进本轮 messages，仅一次）。**v0.4.7+ 催办收紧**（防「hi」被催出一次重命令）：用户这条消息按闲聊判定＝不催；宣告正则只认第一人称（我先/让我/我来/接下来我/下面我/我将/即将/马上/这就/稍等/先看），裸「查看/确认/检查」已删（会误伤选项菜单式回答）；回复以 `?`/`？` 结尾＝在等用户回答＝不催。**v0.4.7+ 闲聊闸门（治「AI 判断错误」：把问候当指令）**：本轮用户消息经纯模块 **`src/chat_intent.ts` 的 `isPureChatter()`** 判定为问候/寒暄/能力询问（整句命中套话，或 ≤16 字符短句且不含动作意图词；「好的/嗯/ok」这类承接上一轮提议的许可短句不算闲聊＝放行）时——①工具执行循环里 **写作类＋生成类**工具一律不执行（`CHAT_WRITING_TOOLS`＋`CHAT_GENERATION_TOOLS` 名单），改回一条拒绝 tool 结果并置状态行「⛔ 已拦下工具 xxx」，让模型转为简短回应＋询问意图；查询类工具不受限；②【工具调用规则】提示词新增第①③条（闲聊不得调写作/生成类命令、违规调用会被插件拦下别重试），原「必须直接发起工具调用」降级为第②条且限定「用户已明确下指令时」。**v0.4.7+ 工具名/参数容错**（模型训练语料里通用 agent 都叫 read_file/grep/write_file，常串名）：`chatExecTool` 入口先 `resolveToolName`——真名原样、`TOOL_NAME_ALIASES` 命中改派（`read_file`→`read_doc`、`list_files`→`list_chapters`、`grep`/`glob`/`search`→`search_vault`、`write_file`/`create_file`/`edit_file`→`save_content_to_file`），改派时 Notice 告知用户；**删除/移动类幻觉名不改派**，switch default 改回 `unknownToolHint`（编辑距离候选＋全量工具名单）让模型下轮自改；参数键宽松（`doc_name|name|path|file`、`chapter_num|chapter|num`、`volume_name|volume|vol`；文档名经 `normalizeDocName` 去《》/.md/目录前缀＋同义表「书籍大纲/年表/…」；章号收「第18章」）。【工具调用规则】⑤限定只能用 tools 清单里的名字、读内置文档一律 `read_doc`。**v0.4.7+ 工具模式异常处置**：①模型配置新增「对话工具调用 chat_tools」下拉（设置页 LLM 配置详情，`getVisibleLlmFields` common 字段；"off"＝该配置的对话从一开始不带工具定义、也不注入【工具调用规则】块；写作命令不受影响）——本地小模型 GGUF 带 21 工具语法约束时输出会碎（实测本地 Strata Qwen3.8-Flash：同一历史带 tools 正文半句即停甚至 content 全 null、不带 tools 完整输出），关掉即恢复；②自动降级扩围：带 tools 请求抛错除「拒参」文案（tool/400/not support…）外，**「输出为空/未返回内容」也去参重试一次**（`toolsDropped` 单次）；③**碎片级自愈三级链**（v0.4.7+）：回复 trim 后 <120 字且 finish≠length/max_tokens＝判定输出崩溃，⑴带 tools → 去参重发（`toolsDropped`）；⑵已不带 tools 且 history>8 条 → **裁历史重试**（`histTrimmed` 单次：本轮 messages 只留 system＋`buildMessages().slice(-4)` 最近 4 条，会话文件/history 完整不动）；⑶仍碎 → 保留输出＋`truncWarn` 状态行＋Notice 诊断（量化小模型有效上下文远小于标称，建议设置页填小「上下文窗口」激活自动压缩、或换强模型）。实测本地 Strata IQ3_S 量化：prompt 257 token 输出 1516 字正常、9k+ token 即 19~67 字半句 EOS（tools 与否都崩）——碎片判定的由来；诊断法＝拿同一 messages 对端点做带/不带 tools 的 A/B 流式对比。
- **多轮流式聊天**：Enter 发送 / Shift+Enter 换行（含中文输入法合成态保护）；「停止生成」仅中断当前轮。**v0.4.7+ 底部按钮布局**：左组＝「压缩上下文」「重新加载对话」「清空对话」，右组＝「发送」「停止生成」（发送为主按钮靠右缘）。**v0.4.7+ 输出截断自动续写**：流结束 `finish_reason="length"`（部分端点写 `max_tokens`，均视为被 `max_tokens` 截断）时，把已输出部分作为 assistant 轮、追加「接着中断处继续写」指令自动续流，气泡与最终回复合并显示；最多续写 3 次，仍被截断则保留警告并提示调大该模型配置的「最大 tokens」。
- **v0.4.7+ 会话持久化＝固定一个《当前对话.md》（案头资料/AI会话/）**：每轮结束（含中断留存的半截回复、仅用户轮）自动把整段对话写到当前书《案头资料/AI会话/**当前对话.md**》（frontmatter：type/story/created_at/updated_at/model/prompt_keep；正文 H2 章节 `## 我`/`## 助手`/`## 摘要（上下文压缩）`，格式与解析在纯模块 `src/chat_session.ts`，文件是普通 Markdown 可人工编辑）；**面板每次打开只加载这一个文件**（不再"挑 mtime 最新的一份"）；目录里没有它但有旧版时间戳会话文件（`对话 YYYY-MM-DD HHMM.md`）时做**一次性改名迁移**（mtime 最新那份 → 固定名，Notice 提示一次）；「**重新加载对话**」按钮＝**对话历史选择器**（`SessionPickerModal`，可搜索：《当前对话.md》标「【当前】」排最前、归档按 mtime 倒序，每项显示文件名·轮数·字数·首句摘要）：选中归档＝**内容互换**——当前文件先改名归档（空骨架＝只有 frontmatter 时直接删，不产空归档），选中文件再改名成《当前对话.md》并载入面板（始终只有一份当前对话、无重复副本）；选中「【当前】」＝单纯从磁盘重读（人工编辑后生效）；第二步改名失败＝回滚第一步的归档，绝不让对话两头落空；目录里没有归档＝退回旧行为（直接重读/接回固定文件）；无当前小说＝只能重读已绑定文件（纯问答不落盘）。「**清空对话**」＝**换会话文件**：先把当前会话文件改名归档为《对话 YYYY-MM-DD HHMM.md》（名字取自 frontmatter `created_at`，同分钟撞名加 `-2`），再原位新建空的《当前对话.md》承接新内容，历史会话因此留在 AI会话 文件夹可人工翻阅；对话本来为空则清空＝无操作（不产生空归档文件）；改名失败＝不新建空文件、保留原绑定并提示；已绑定会话切书后仍写回原文件；**无当前小说（纯问答）不落盘**、仅内存。顶部会话状态行：绑定文件路径 · 条目/字数 · 长对话软提醒（未绑定时显示"发送后写入当前书《案头资料/AI会话/当前对话.md》"）。
- **v0.4.6+ 上下文压缩（手动＋自动，v0.4.7+ 双轨制）**：显示与发送分两条轨——`history`（显示轨：气泡＋会话文件，**完整永不清空**）与 `promptTurns`（提示词轨：实际每轮发送的内容，＝可选摘要轮＋显示轨末尾保留窗若干轮）。新user/assistant轮同时追加两轨；**压缩只重写提示词轨**：保留窗外的更早轮次交当前模型并入摘要（`## 摘要（上下文压缩）` 只折入系统提示词发送、不在气泡显示），显示轨与会话文件原样保留全部对话。文件仍只有一个（显示轨全文＋摘要节＋frontmatter `prompt_keep`＝提示词轨保留窗轮数），读回经 `applyLoadedTurns` 拆双轨（旧文件无该字段＝提示词轨全量，兼容）。「压缩上下文」按钮把提示词轨保留窗（最近 2 轮）之外的轮次连同旧摘要合并成一条**新摘要轮**；滚动式：再压缩时旧摘要并入新摘要。压缩进行中可「停止生成」中止（两轨原样）；不足保留窗＋4 条时拒绝并提示；成功后会话文件重写（含新 prompt_keep）。**自动触发（发送前判定）**：每份模型配置可填「上下文窗口 context_window」（token 数；留空按模型名 `-128k` 类后缀推断，**v0.4.7+ 推不出回落缺省窗口 8192（`DEFAULT_CHAT_WINDOW`）——自动压缩不再因窗口未知而关闭**，实窗更大请填 context_window 覆盖）——发送前按**完整预算**估算「系统提示词（含摘要块＋工具规则）＋历史 user/assistant 轮＋本轮 @展开文本＋工具定义＋单轮工具结果预留（**开销合计按 窗口/6 封顶**，v0.4.7+ 由 1/3 收紧）＋回复预留（min(max_tokens, **窗口/6**)，由 1/4 收紧）」，超过 窗口×阈值%（全局设置「对话自动压缩阈值」，缺省 75、0＝关闭）即先压缩再发送；压缩后仍超限则**自适应保留窗**（2 轮→1 轮）继续压，最多 3 次。**v0.4.7+ 防抖（用户反馈「压得太频繁」）**：①触发后压到「阈值 −10 个百分点」（下限 50%）为止、不是刚好压线；②待压切片估算 < `autoCompressMinGain(窗口)`＝max(200, 窗口/24) 就**跳过压缩**（额外一次 LLM 调用换不来空间），并在状态行说明大头在哪；③两处预留收紧（1/3＋1/4 → 各 1/6）——缺省 8192 窗口下原先光预留就吃掉约 58%，等于没聊几句就每轮都压。会话行实时显示「提示词估算 ~N token / 窗口 M ≥X% 自动压缩（压到 Y% 以下、可压内容太少则跳过）」。压缩被「停止生成」中止＝本轮不发送；压缩失败/历史太短＝照发并带状态警告。会话行实时显示「提示词估算 ~N token / 窗口 M ≥X% 自动压缩」。
- **回复落盘（v0.4.6+ 起无逐条按钮）**：助手气泡下方**不再**显示「保存到文件」按钮（用户反馈每次交互都出现过于打扰，已移除 `addSaveAction`/`saveReply`/`writeReply` 与构造注入 `getDefaultSaveDir`）；逐轮内容本就由 `saveSession()` 自动写入《AI会话/》会话文件、需要单独存文件时改走对话工具 `save_content_to_file`（SaveReplyModal 人证闸门不变）。
- **@ 引用功能**：两种形式——`@[[相对路径]]`（弹窗插入、可含空格）与 `@相对路径`（手输，须含 `/` 或扩展名防误伤邮箱）；支持行范围（`:起-止`、空格分隔、紧贴 token 尾的数字）；键入 @ 弹候选列表（vault 文件按路径过滤、排除 `_resources`、v0.4.3+ 不截断全量列出）；Enter 发送时 token 原位内联展开为「=== 路径（第X–Y行 / 全文）=== + 带行号正文」片段（模型直接看到原文），气泡回显原始输入（保留 @ 标记）。
- **每轮系统提示词与上下文**：请求前置对话专用系统提示词（友好助手身份 + 当前小说上下文快照〔写作上下文 + 当前章节正文截断 6000 字〕；**v0.3.5+** 旧「创作规范指南」三层指南块已随写作指南体系废弃、不再注入）；多轮历史经原生 messages 传递。顶部首行显示当前小说·章节，切书/切章等变更后由 main.ts 主动刷新（钩子挂在 saveSettings 与状态落盘回调两条必经路径，任何命令的状态变更无需逐处埋点）。
