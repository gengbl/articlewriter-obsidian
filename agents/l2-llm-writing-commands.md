# L2 · LLM 写作命令（含「生成过程」面板）

## 模块概要

LLM 写作类命令（`write-chapter`/`continue-writing`/`rewrite-chapter`/`polish-text`/`deai-clean`/`typo-check`/`review-chapter`/`write-chapters-consecutive`/`vol-outline-generate`/`book-outline-generate`/`planning-guide`/`planning-guide-worldview`）共用统一流程：prompt 组装在 `src/prompts.ts`，调用层在 `src/llm_client.ts`，结果落盘+场景同步走 `story_manager.ts`（`vol-outline-generate` 为卷级生成、落盘走 `setVolumeOutline`；**v0.2.x+ 增量分段落盘**：输出拆成小段防长单次输出断开——第 0 步【卷设计】段（补全模式跳过）＋其后每个章号一个 `## 第N章` 小节，全程同一面板实例、每段实时流式展示并生成完立即落盘再继续下一段，Esc/关面板中止整轮但已落盘段落保留；v0.2.x+ `book-outline-generate` 为书级生成、平铺与有卷两模式通用、落盘走 `setGlobalOutline`——已有非空时弹覆盖/追加二选一，追加保留原文剥首部 H1 后拼接；两者均不走章节管线，其余流程一致；**v0.2.13+ `planning-guide`（策划指南）**：AI 流式生成书级单文件 `<书名>/策划指南.md`（固定十节既定规划约束，不做三层合并），system 消息复用 `BOOK_OUTLINE_GEN_SYSTEM_PROMPT`，输入＝书籍信息＋世界观＋全书大纲＋卷列表＋已有章节及其摘要；**v0.2.x+ 生成前必问目标总章数**（`promptChapterCountInput` 必填、Esc 取消）——各节位置（抬升节点/伏笔埋设与回收/高潮落位等）一律以该总章数为基准表述（修复自动生成时未使用用户输入章数的问题）；已存在且非空时弹确认（整体重写/取消）、重写以现有内容为既定事实约束（可调整表述、不得改变已确立事实）；落盘走 `setPlanningGuide`。**v0.2.x+ `planning-guide-worldview`（生成策划指南·仅世界观）**：早期规划场景——输入仅书籍信息＋世界观设定（跳过大纲/卷/章节加载），无章节时「十·连续性基线」改以世界观设定为据整理既定事实；其余流程（已有非空弹确认→问目标章数→流式→自动落盘）与 `planning-guide` 一致。**平铺（无卷）模式**（`state.use_volumes===false`）：策划指南 prompt 加显式禁卷 req（全书无卷结构、位置一律用章号表述）、第二节位置措辞改「第几章附近」、开篇约束句去「卷级」；`book-outline-generate` 平铺分支同样加显式禁卷 req（不得输出卷划分/卷声明行/卷引用）且【策划规范】req 注明「若含卷划分/卷引用则忽略其卷结构、仅按章号规划」——修复平铺模式下注入的卷导向策划规范导致模型跟随输出卷结构的 bug。三个大纲生成命令（`book-outline-generate`/`vol-outline-generate` 含无卷兜底批量路径/`book-outline-to-volumes`）生成前经 main.ts `ensurePlanningGuide` 确保该文件存在——缺失时先 LLM 流式自动生成并落盘再使用（无确认弹窗），**软依赖**：生成失败（中止/连续 3 次空结果）仅 Notice 告警、不带【策划规范】块继续；**v0.2.x+ `ensurePlanningGuide` 透传目标章数**（`book-outline-generate` 传用户输入章数、`book-outline-to-volumes` 传各卷目标章数之和，使自动生成的策划指南与本次大纲规划同基准；`vol-outline-generate` 两调用点不传——VolumeDeclaration 只有卷名/描述、无法算全书总数）；非空时其内容以【策划规范 · 本书既定规划（生成大纲时必须遵循、不得违背）】块注入提示词【书籍信息】之后——卷级走共享 `volOutlineContextParts`（增量每一段都可见）、书级另加一条 req 行；不参与正文写作命令/聊天面板的提示词）；所有生成结果先在统一「生成过程」面板内流式预览并经「保存/不保存」确认才写盘（设计决策见 [l1-overview.md](./l1-overview.md)）——**例外是 `write-chapters-consecutive`（连续编写，v0.2.10+）、卷大纲生成（`vol-outline-generate`＋其两条批量路径，v0.2.x+）与策划指南（`planning-guide`/`planning-guide-worldview`，v0.2.13+/v0.2.x+，含三个大纲生成命令缺失时触发的自动生成路径）**：逐章/逐段自动保存免确认，面板经 `GenProgressView.finishAuto(message?, elapsedLabel?)` 直接收尾（submitted 置真、resolveDone(true)、追加一行 ok 日志；elapsedLabel 自定义用时前缀，默认「本章用时」、卷大纲用「段落用时」），失败态（streamState≠streaming）finishAuto 空操作、由命令侧 Notice 停止。各命令语义/参数/坑位速查见 [command-reference.md](./command-reference.md)；摘要延迟生成管线见 [l3-summary-pipeline.md](./l3-summary-pipeline.md)，新增命令标准流程与 main.ts 辅助方法见 [l3-main-ts-flow.md](./l3-main-ts-flow.md)。

- **「生成过程」面板双阶段复用同一实例**（常驻 ItemView，可停靠任意区域）：①摘要延迟生成日志阶段——每个 LLM 任务追加一行带时间戳日志并自动滚底、本轮结束追加「✓ 摘要就绪」；②章节/报告流式阶段——流式预览正文 + 「保存/不保存」CTA；思考型模型的思考过程在灰色区块实时显示（不写入正文），正文为空但思考非空时给出针对性报错而非盲目重试。Esc 或「停止生成」＝abort 当前会话；关面板未决会话按放弃收尾；重试前清屏。**v0.2.x+ 生成计时**：流式过程状态行实时显示已用时，完成/失败时定格总用时；连续编写每章 ok 行显示本章用时、结束汇总 Notice 显示整轮总用时。

- **`typo-check`（错别字检测）**：LLM 全文扫描当前章错字并加下划线标记、附建议改正。与其余命令的差异——**非流式**（`chatCompletion` 一次性返回，因需确定性校验全文回显）、**输出协议为回显式**：`<MARKED>…</MARKED>` 内逐字回显全文并把每个错字包成 `<u>错</u>`（其余字符一字不改），其后跟 JSON 数组 `[{"wrong":"…","right":"…"}]`（无错字为 `[]`）。**确定性校验**：剥掉 MARKED 段内 `<u>/</u>` 后必须与原文逐字一致（容忍模型把标记各占一行引入的首尾单个换行），不一致自动重试最多 3 次；3 次仍失败 → Notice「✗ …全文回显漂移，章节文件未改动」不动文件。落盘格式 `<span style="text-decoration:underline" title="建议改为：X">错字</span>`（无建议时省略 title）——**结果性标记有意落盘**（区别于去AI味的过程性标红、保存前剥掉），读回经 `stripAiWordMarks` 自动剥离故重跑幂等、摘要/字数/导出不受影响。建议映射：suggestions 条数==marks 条数按序一一对应，否则按 wrong===mark 文本匹配（每条只用一次），都匹配不到则该处无 title。面板预览＝顶部「共发现 N 处错别字：1. X → Y」清单 + `---` + 带 span 的全文（纯文本渲染、span 以源码可见属预期），确认后 `setChapterBody` 全量覆盖。max_tokens 取 `max(cfg.max_tokens, ceil(正文长×2)+1024)` 保证回显预算。
