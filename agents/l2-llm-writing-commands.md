# L2 · LLM 写作命令（含「生成过程」面板）

## 模块概要

为卷级生成、落盘走 `setVolumeOutline`；**v0.2.x+ 增量分段落盘**：输出拆成小段防长单次输出断开——第 0 步【卷设计】段（补全模式跳过）＋其后每个章号一个 `## 第N章` 小节，全程同一面板实例、每段实时流式展示并生成完立即落盘再继续下一段（**v0.2.x+ 提示词注入已生成各段经 `outlineSoFarContext` 裁剪**——≤3 段全列、>3 段仅列最近 3 章并在头部注明省略章数，避免每步 O(N²) 重复上传；紧邻前一章恒在尾部，因果链不断），Esc/关面板中止整轮但已落盘段落保留；v0.2.x+ `book-outline-generate` 为书级生成、平铺与有卷两模式通用、落盘走 `setGlobalOutline`（**两模式输出形态与弹窗**：平铺＝弹窗问目标章数、输出恰好 N 个 `## 第N章` `buildBookOutlineContinuePrompt` 续写，段末缺「章末钩子」判定为截断并重生成该章，直到覆盖或无法继续）——已有非空时弹覆盖/追加二选一（仅完整生成），追加保留原文剥首部 H1 后拼接；**v0.2.x+ - **「生成过程」面板双阶段复用同一实例**（常驻 ItemView，可停靠任意区域）：①摘要延迟生成日志阶段——每个 LLM 任务追加一行带时间戳日志并自动滚底、本轮结束追加「✓ 摘要就绪」；②章节/报告流式阶段——流式预览正文 + 「保存/不保存」CTA；思考型模型的思考过程在灰色区块实时显示（不写入正文），正文为空但思考非空时给出针对性报错而非盲目重试。Esc 或「停止生成」＝abort 当前会话；关面板未决会话按放弃收尾；重试前清屏。**v0.2.x+ 生成计时**：流式过程状态行实时显示已用时，完成/失败时定格总用时；连续编写每章 ok 行显示本章用时、结束汇总 Notice 显示整轮总用时。

- **v0.2.21+ 摘要随写（正文＋摘要同响应输出、分别落盘）**：`/write`、`/write-consecutive`、`/continue`、`/rewrite` 四命令在 `use_summaries` 未关闭时，要求模型在同一响应末尾追加 `<SUMMARY>` 块（200~300 字，四条标准＝关键情节/人物状态/伏笔与悬念/新增信息；/continue 只覆盖新续写部分）；插件确定性解析后正文照旧落盘、摘要分别落盘《章节摘要.md》——哈希按已存正文重算，下次上下文组装判「新鲜」直接复用，省掉单独摘要 LLM 调用。解析失败（无完整块/摘要为空）静默回落到既有延迟生成（不重试不阻断）；正文为空（仅输出摘要块）按生成失败处理。面板流式期间显示原始输出，解析后、保存确认前刷新为纯正文预览；完成 Notice 追加「摘要：已随正文一并保存」（连续编写汇总带份数）。实现细节见 [l3-summary-pipeline.md](./l3-summary-pipeline.md)。

- **v0.2.24+ 写作阶段身份加强（identity_boost）**：设置页写作阶段模型配置区每个阶段（策划方案生成 / 书籍大纲和卷级大纲生成 / 文章大纲生成 / 编写文章）各一个独立 textarea；非空时注入到该阶段 system prompt 末尾的【身份加强】块（`assembleSystemPrompt` 第 4 个可选参数），用于为特定阶段定制 AI 角色定位或语气风格；留空=不注入，不影响其他阶段。控制键格式 `writing_phases.{idx}.identity_boost`（idx 0–3）。**注入范围（v0.2.x+ 修复：此前仅阶段 3 部分正文命令注入，阶段 0/1/2 运行时与导出均未注入本阶段值）**——全部创作阶段运行时＋export-ai-prompts 预览同口径注入：①阶段 0 策划指南（`cmdPlanningGuideWorldview`＋`ensurePlanningGuide` 自动生成路径，system 复用 `BOOK_OUTLINE_GEN_SYSTEM_PROMPT`）；②阶段 1 书级大纲（完整生成／extend 续写／平铺续写 `runFlatOutlineContinuation`）＋卷级大纲（`genVolOutlineIncremental` 全路径：单卷完整/继续、零卷兜底批量、book-outline-to-volumes 批量）；共享 runner 新增必填 `systemPrompt` opts 字段、调用方按所属阶段组装后传入；③阶段 2 AI 拆分兜底逐章循环。**机械/辅助任务有意不注入**（用户决策）：`/typo`、`/analyze-cast`、章节/卷摘要延迟生成、`autoCleanAi` 去AI味——输出协议严格（全文回显/固定格式），注入身份文本有漂移风险。**双标记防护**：存储值本身可能已带「【身份加强】」前缀（旧版默认文本即如此）——`assembleSystemPrompt` 追加前先剥掉值的前导标记，输出只出现一个【身份加强】块。详见 [l3-main-ts-flow.md](./l3-main-ts-flow.md)。

- **v0.2.22+ 全部 LLM 调用按写作阶段取模型（阶段分类）**：所有 LLM 调用一律走 `getPhaseLlmSetup(phaseIndex)`——优先该阶段的 `llm_config_name`，未指定回落第一个配置 `cfgs[0]`；**对话框选择的 `chat_model` 与旧版激活态 `active_llm` 均不参与阶段回退**（切换对话框模型/激活态不影响任何命令用哪个模型）。四阶段归属：①阶段 0 策划方案生成＝`planning-guide-worldview`（含大纲生成前 `ensurePlanningGuide` 触发的自动补全）；②阶段 1 书籍大纲和卷级大纲生成＝`book-outline-generate` / `vol-outline-generate`（含 `autoCreateVolumesAndGenOutlines`、`book-outline-to-volumes` 批量流程内的逐卷生成）；③阶段 2 文章大纲生成＝`vol-outline-to-chapters` 的 AI 拆分兜底（本地章标记解析不触发 LLM）；④阶段 3 编写文章＝全部正文命令（`write`/`continue`/`rewrite`/`polish`/`deai`/`fix-refs`/`typo`/`review`/`analyze-cast`/`write-consecutive`）＋辅助任务（章节摘要/卷摘要延迟生成回调、剧本转换、LLM 连接测试）。对话框自身保持独立：下拉取模 `chat_model || active_llm`（llm_chat_view 自读 conf，不走阶段映射）。「生成过程」面板标题显示本次调用实际使用的阶段模型名。export-ai-prompts 各节同步按所属阶段标注模型配置来源（原孤儿导出节「生成策划指南 (/planning-guide)」不在功能点清单内、不可达，已删除）。

- **v0.2.21+ 正文「第N章」章节编号引用：提示词禁令＋确定性检测兜底**：`/write`、`/continue`、`/rewrite` 三 builder 均注入统一禁令常量 `CHAPTER_REF_BAN`（正文不得出现「第N章」类章节编号的元引用，提及前文事件/伏笔改用具体内容指代，章节编号只允许出现在标题行）。代码侧确定性兜底：`findChapterRefLeaks(content)` 逐行正则扫描 `/第[0-9一二三四五六七八九十百千零两]+章/g`，豁免 MD 标题行与纯文本章题行（含裸章题行），至多返回 10 处 `{line, snippet}`；四命令（/write、/write-consecutive、/continue、/rewrite）在**新生成内容**上调用 `warnChapterRefs`——命中即非阻断 Notice 列前 5 处行号与片段、建议人工检查（不修改内容、不阻断保存）。检测时机刻意选在合并旧正文之前（追加/续写模式），避免误报既有正文。**手动修复命令 `fix-chapter-refs`（/fix-refs）**：弹窗问章节号——**留空＝全书所有章节都检测修复**（按阅读序逐章处理）、**填数字＝只修指定章节**（跨卷同号逐个确认）；每个目标章对全文跑同一豁免口径的 `findChapterRefSentences`（命中句按句末标点切分定位、同句多处命中只记一次、至多 10 句）——无正文/无命中的章静默跳过；有命中则单轮 LLM 逐句重写（`buildChapterRefFixPrompt`，输出协议同去AI味的「N：改写句」，基础系统提示词全书共用一份），代码侧确定性校验后**从后往前原位替换**（改写为空或仍含「第N章」的句子跳过保留原文），`setChapterBody` 全量覆盖**自动保存（无预览确认）**；结束汇总 Notice（改写保存章数／无引用跳过章数／无正文跳过章数／未成功章数＋共改写句数／跳过句数）。与自动检测的关系：自动检测是生成后非阻断提醒，本命令是按需的手动修复入口。

- **`typo-check`（错别字检测）**：LLM 全文扫描当前章错字并加下划线标记、附建议改正。与其余命令的差异——**非流式**（`chatCompletion` 一次性返回，因需确定性校验全文回显）、**输出协议为回显式**：`<MARKED>…</MARKED>` 内逐字回显全文并把每个错字包成 `<u>错</u>`（其余字符一字不改），其后跟 JSON 数组 `[{"wrong":"…","right":"…"}]`（无错字为 `[]`）。**确定性校验**：剥掉 MARKED 段内 `<u>/</u>` 后必须与原文逐字一致（容忍模型把标记各占一行引入的首尾单个换行），不一致自动重试最多 3 次；3 次仍失败 → Notice「✗ …全文回显漂移，章节文件未改动」不动文件。落盘格式 `<span style="text-decoration:underline" title="建议改为：X">错字</span>`（无建议时省略 title）——**结果性标记有意落盘**（区别于去AI味的过程性标红、保存前剥掉），读回经 `stripAiWordMarks` 自动剥离故重跑幂等、摘要/字数/导出不受影响。建议映射：suggestions 条数==marks 条数按序一一对应，否则按 wrong===mark 文本匹配（每条只用一次），都匹配不到则该处无 title。面板预览＝顶部「共发现 N 处错别字：1. X → Y」清单 + `---` + 带 span 的全文（纯文本渲染、span 以源码可见属预期），确认后 `setChapterBody` 全量覆盖。max_tokens 取 `max(cfg.max_tokens, ceil(正文长×2)+1024)` 保证回显预算。

- **`export-ai-prompts`（导出AI提示词，确定性无 LLM）**：弹出功能点选择弹窗（checkbox 列表 + 全选/全不选；**整行可点**——点击行内任意位置含 checkbox/文字/说明区即切换该行选中态，键盘空格同路径），用户勾选后只导出选中功能点对应文件（未勾选的完全跳过、不写入任何条目），「AI提示词（导出说明）」元数据条目始终包含不参与选择。把上述全部 AI 阶段（章域 8 + 大纲域 5 + 摘要域 3）在当前小说盘上数据下**会实发的 system/user 提示词**逐节导出到书根《AI提示词/》子目录各独立 `.md` 文件（`manager.savePromptExportDocs`，案头资料、重复导出整体覆盖），供逐个喂本地模型比对输出。行为约定：①导出全程零 LLM 调用，与各 cmdXxx 复用同一构建函数与参数；②弹窗输入取默认基准——文本弹窗留空、章数弹窗 `defaultCount=max(现有章数,1)`、策划指南卷数量弹窗取现有卷数（`loadVolumes` 计数，不弹问、0 卷＝不按卷组织；**v0.2.25+**）（文档头部集中声明此口径）；③按盘上现状判定「现在会不会触发」，不会触发的阶段只写跳过原因（`exportSkipSection`），例如去AI味无命中、AI 拆章在章标记已存在时不触发、摘要已新鲜时延迟生成不再调用——唯一例外 /write：激活章已有正文时运行时不触发，但仍照常组装导出提示词（节内备注「假设触发时实发」），便于随时调试不必切空章；④增量链（卷设计→逐章、AI 拆章逐章、analyze-cast 逐章、书级大纲续写）只导出首步，依赖前一步输出处用占位符注明；⑤每节标注模型配置来源（v0.2.22+ 全部 16 节均走阶段映射 getPhaseLlmSetup(phaseIndex)、旧全局激活分支已删 + cfg.name/model_name）与运行时显式参数覆盖；⑥章域基准=写字台当前激活章（无选择器）、大纲/卷摘要域基准=当前卷；⑦不触发任何写盘副作用（不调 `ensurePlanningGuide`、不生成摘要），只读判定——写作上下文中的摘要同样不触发延迟生成：已存新鲜摘要照放、缺失处填占位符「（此处有摘要，尚未生成）」（无成员章摘要的卷运行时也跳过、不占槽，故不填）。实现：`cmdExportPrompts`/`buildPromptExportDoc(story, selectedFeatures?)`（selectedFeatures 为空时导出全部向后兼容，非空时 trySec 内未命中则 return 跳过；每节 `trySec` 独立 try/catch 保证单节失败不拖垮整篇、`fenceBlock` 按内容反引号自动升级围栏），见 [command-reference.md](./command-reference.md)。
