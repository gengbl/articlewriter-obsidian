# L2 · LLM 写作命令（含「生成过程」面板）

## 模块概要

LLM 写作类命令（`write-chapter`/`continue-writing`/`rewrite-chapter`/`polish-text`/`deai-clean`/`fix-chapter-refs`/`typo-check`/`review-chapter`/`write-chapters-consecutive`/`vol-outline-generate`/`book-outline-generate`/`planning-guide`/`planning-guide-worldview`）共用统一流程：prompt 组装在 `src/prompts.ts`，调用层在 `src/llm_client.ts`，结果落盘+场景同步走 `story_manager.ts`（`vol-outline-generate` 为卷级生成、落盘走 `setVolumeOutline`；**v0.2.x+ 增量分段落盘**：输出拆成小段防长单次输出断开——第 0 步【卷设计】段（补全模式跳过）＋其后每个章号一个 `## 第N章` 小节，全程同一面板实例、每段实时流式展示并生成完立即落盘再继续下一段（**v0.2.x+ 提示词注入已生成各段经 `outlineSoFarContext` 裁剪**——≤3 段全列、>3 段仅列最近 3 章并在头部注明省略章数，避免每步 O(N²) 重复上传；紧邻前一章恒在尾部，因果链不断），Esc/关面板中止整轮但已落盘段落保留；v0.2.x+ `book-outline-generate` 为书级生成、平铺与有卷两模式通用、落盘走 `setGlobalOutline`（**平铺大章数自动续写**：生成后检测 1..N 章标记覆盖度，缺章时按 10 章一段调用 `buildBookOutlineContinuePrompt` 续写，段末缺「章末钩子」判定为截断并重生成该章，直到覆盖或无法继续）——已有非空时弹覆盖/追加二选一（仅完整生成），追加保留原文剥首部 H1 后拼接；**v0.2.x+ 平铺模式现有大纲以紧凑索引注入提示词**（首个章标记前前言原样保留、每章只留章标题行＋主线行，百章大纲约 73% token 缩减）防本地模型上下文窗口溢出，有卷模式保持全量；**v0.2.x+ 继续生成**：现有大纲非空时先选「完整生成 / 按已有进度继续」（`promptOutlineGenMode`，空大纲保持原流程直接问目标章数）——继续模式问「要增加的章数 N」、目标总章数 = 已有最大章号 M + N（卷级与书级平铺 M = `## 第N章` 最大章号、书级有卷 M = 卷声明最大结束章 `maxDeclaredEndChapter`，识别不到则 Notice 并中止），直接拼到原文末尾落盘（无覆盖/追加二选一）：卷级走 `genVolOutlineIncremental`（hasDesign=false、M+1..count 逐章 supplementMode 续写、原文 preamble 作卷设计参考）、书级平铺走 `runFlatOutlineContinuation`（与截断兜底共用，从 M 之后逐章续写、末章残缺被裁掉重生成时按 startNum 一并算入新内容）、书级有卷走 `buildBookOutlineExtendPrompt`（只追加覆盖 M+1..count 的新卷声明行＋更新结局段，`trimExtendPreamble` 丢模型可能的前言）；各提示词均带「故事在目标章自然收束结尾」字样（目标章 = count，完整生成同样适用）；两者均不走章节管线，其余流程一致；**v0.2.13+ `planning-guide`（策划指南）**：AI 流式生成书级单文件 `<书名>/策划指南.md`（固定十节既定规划约束，不做三层合并；**建书时已随 rootDocTemplates 播种空模板**，留空即由大纲生成前自动补内容），system 消息复用 `BOOK_OUTLINE_GEN_SYSTEM_PROMPT`，输入＝书籍信息＋世界观＋全书大纲＋卷列表＋已有章节及其摘要；**v0.2.x+ 生成前必问目标总章数**（`promptChapterCountInput` 必填、Esc 取消）——各节位置（抬升节点/伏笔埋设与回收/高潮落位等）一律以该总章数为基准表述（修复自动生成时未使用用户输入章数的问题）；已存在且非空时弹确认（整体重写/取消）、重写以现有内容为既定事实约束（可调整表述、不得改变已确立事实）；落盘走 `setPlanningGuide`。**v0.2.x+ `planning-guide-worldview`（生成策划指南·仅世界观）**：早期规划场景——输入仅书籍信息＋世界观设定（跳过大纲/卷/章节加载），无章节时「十·连续性基线」改以世界观设定为据整理既定事实；其余流程（已有非空弹确认→问目标章数→流式→自动落盘）与 `planning-guide` 一致。**平铺（无卷）模式**（`state.use_volumes===false`）：策划指南 prompt 加显式禁卷 req（全书无卷结构、位置一律用章号表述）、第二节位置措辞改「第几章附近」、开篇约束句去「卷级」；`book-outline-generate` 平铺分支同样加显式禁卷 req（不得输出卷划分/卷声明行/卷引用）且【策划规范】req 注明「若含卷划分/卷引用则忽略其卷结构、仅按章号规划」——修复平铺模式下注入的卷导向策划规范导致模型跟随输出卷结构的 bug。三个大纲生成命令（`book-outline-generate`/`vol-outline-generate` 含无卷兜底批量路径/`book-outline-to-volumes`）生成前经 main.ts `ensurePlanningGuide` 确保该文件存在——缺失时先 LLM 流式自动生成并落盘再使用（无确认弹窗），**软依赖**：生成失败（中止/连续 3 次空结果）仅 Notice 告警、不带【策划规范】块继续；**v0.2.x+ `ensurePlanningGuide` 透传目标章数**（`book-outline-generate` 传用户输入章数、`book-outline-to-volumes` 传各卷目标章数之和，使自动生成的策划指南与本次大纲规划同基准；`vol-outline-generate` 两调用点不传——VolumeDeclaration 只有卷名/描述、无法算全书总数）；非空时其内容以【策划规范 · 本书既定规划（生成大纲时必须遵循、不得违背）】块注入提示词【书籍信息】之后——卷级走共享 `volOutlineContextParts`（增量每一段都可见）、书级另加一条 req 行；不参与正文写作命令/聊天面板的提示词；**v0.2.x+ 三个大纲生成命令与 AI 兜底逐章拆分生成前也调 `loadWriterGuides`**（触发《写作指南汇总.md》检测更新重建，批量循环整批只查一次），其去注释正文经 VolOutlineGenInput/BookOutlineGenInput `guideText?` 在【策划规范】后插【创作规范 · 本项目要求必须遵守的创作规范（生成大纲时必须遵循、不得违背）】块——与编写章节同一口径）；**v0.2.x+ 张力规则（情节张力/节奏规则）**：独立存储于插件数据目录 `TENSION_RULES.md`（首启 `ensureTensionRulesFile` 从内置默认播种——仓库根 `TENSION_RULES.md` 经 `.md=text` 打包进 main.js、`src/tension_rules_default.ts` 导出 `DEFAULT_TENSION_RULES`；仅缺失时写盘，运行时读盘上内容故用户直接编辑即生效，读不到/为空回落内置默认），三条大纲/策划生成路径（`vol-outline-generate` 含无卷兜底批量路径 / `book-outline-generate` / `planning-guide`·`planning-guide-worldview` 含 `ensurePlanningGuide` 触发的自动生成路径）生成前经 `loadTensionRules` 加载并注入独立【张力规则 · 情节张力/节奏规则（生成大纲时必须遵循）】块（策划指南路径文案为「生成策划指南时必须遵循」）——大纲路径放【创作规范】块之后、策划指南无【创作规范】块故放【书籍信息】后；不进正文写作命令提示词；export-ai-prompts 预览视图与运行时同口径（读盘、缺失回落内置默认）；所有生成结果先在统一「生成过程」面板内流式预览并经「保存/不保存」确认才写盘（设计决策见 [l1-overview.md](./l1-overview.md)）——**例外是 `write-chapters-consecutive`（连续编写，v0.2.10+）、卷大纲生成（`vol-outline-generate`＋其两条批量路径，v0.2.x+）与策划指南（`planning-guide`/`planning-guide-worldview`，v0.2.13+/v0.2.x+，含三个大纲生成命令缺失时触发的自动生成路径）**：逐章/逐段自动保存免确认，面板经 `GenProgressView.finishAuto(message?, elapsedLabel?)` 直接收尾（submitted 置真、resolveDone(true)、追加一行 ok 日志；elapsedLabel 自定义用时前缀，默认「本章用时」、卷大纲用「段落用时」），失败态（streamState≠streaming）finishAuto 空操作、由命令侧 Notice 停止。各命令语义/参数/坑位速查见 [command-reference.md](./command-reference.md)；摘要延迟生成管线见 [l3-summary-pipeline.md](./l3-summary-pipeline.md)，新增命令标准流程与 main.ts 辅助方法见 [l3-main-ts-flow.md](./l3-main-ts-flow.md)。

- **「生成过程」面板双阶段复用同一实例**（常驻 ItemView，可停靠任意区域）：①摘要延迟生成日志阶段——每个 LLM 任务追加一行带时间戳日志并自动滚底、本轮结束追加「✓ 摘要就绪」；②章节/报告流式阶段——流式预览正文 + 「保存/不保存」CTA；思考型模型的思考过程在灰色区块实时显示（不写入正文），正文为空但思考非空时给出针对性报错而非盲目重试。Esc 或「停止生成」＝abort 当前会话；关面板未决会话按放弃收尾；重试前清屏。**v0.2.x+ 生成计时**：流式过程状态行实时显示已用时，完成/失败时定格总用时；连续编写每章 ok 行显示本章用时、结束汇总 Notice 显示整轮总用时。

- **v0.2.21+ 摘要随写（正文＋摘要同响应输出、分别落盘）**：`/write`、`/write-consecutive`、`/continue`、`/rewrite` 四命令在 `use_summaries` 未关闭时，要求模型在同一响应末尾追加 `<SUMMARY>` 块（200~300 字，四条标准＝关键情节/人物状态/伏笔与悬念/新增信息；/continue 只覆盖新续写部分）；插件确定性解析后正文照旧落盘、摘要分别落盘《章节摘要.md》——哈希按已存正文重算，下次上下文组装判「新鲜」直接复用，省掉单独摘要 LLM 调用。解析失败（无完整块/摘要为空）静默回落到既有延迟生成（不重试不阻断）；正文为空（仅输出摘要块）按生成失败处理。面板流式期间显示原始输出，解析后、保存确认前刷新为纯正文预览；完成 Notice 追加「摘要：已随正文一并保存」（连续编写汇总带份数）。实现细节见 [l3-summary-pipeline.md](./l3-summary-pipeline.md)。

- **v0.2.21+ 正文「第N章」章节编号引用：提示词禁令＋确定性检测兜底**：`/write`、`/continue`、`/rewrite` 三 builder 均注入统一禁令常量 `CHAPTER_REF_BAN`（正文不得出现「第N章」类章节编号的元引用，提及前文事件/伏笔改用具体内容指代，章节编号只允许出现在标题行）。代码侧确定性兜底：`findChapterRefLeaks(content)` 逐行正则扫描 `/第[0-9一二三四五六七八九十百千零两]+章/g`，豁免 MD 标题行与纯文本章题行（含裸章题行），至多返回 10 处 `{line, snippet}`；四命令（/write、/write-consecutive、/continue、/rewrite）在**新生成内容**上调用 `warnChapterRefs`——命中即非阻断 Notice 列前 5 处行号与片段、建议人工检查（不修改内容、不阻断保存）。检测时机刻意选在合并旧正文之前（追加/续写模式），避免误报既有正文。**手动修复命令 `fix-chapter-refs`（/fix-refs）**：弹窗问章节号——**留空＝全书所有章节都检测修复**（按阅读序逐章处理）、**填数字＝只修指定章节**（跨卷同号逐个确认）；每个目标章对全文跑同一豁免口径的 `findChapterRefSentences`（命中句按句末标点切分定位、同句多处命中只记一次、至多 10 句）——无正文/无命中的章静默跳过；有命中则单轮 LLM 逐句重写（`buildChapterRefFixPrompt`，输出协议同去AI味的「N：改写句」，基础系统提示词全书共用一份），代码侧确定性校验后**从后往前原位替换**（改写为空或仍含「第N章」的句子跳过保留原文），`setChapterBody` 全量覆盖**自动保存（无预览确认）**；结束汇总 Notice（改写保存章数／无引用跳过章数／无正文跳过章数／未成功章数＋共改写句数／跳过句数）。与自动检测的关系：自动检测是生成后非阻断提醒，本命令是按需的手动修复入口。

- **`typo-check`（错别字检测）**：LLM 全文扫描当前章错字并加下划线标记、附建议改正。与其余命令的差异——**非流式**（`chatCompletion` 一次性返回，因需确定性校验全文回显）、**输出协议为回显式**：`<MARKED>…</MARKED>` 内逐字回显全文并把每个错字包成 `<u>错</u>`（其余字符一字不改），其后跟 JSON 数组 `[{"wrong":"…","right":"…"}]`（无错字为 `[]`）。**确定性校验**：剥掉 MARKED 段内 `<u>/</u>` 后必须与原文逐字一致（容忍模型把标记各占一行引入的首尾单个换行），不一致自动重试最多 3 次；3 次仍失败 → Notice「✗ …全文回显漂移，章节文件未改动」不动文件。落盘格式 `<span style="text-decoration:underline" title="建议改为：X">错字</span>`（无建议时省略 title）——**结果性标记有意落盘**（区别于去AI味的过程性标红、保存前剥掉），读回经 `stripAiWordMarks` 自动剥离故重跑幂等、摘要/字数/导出不受影响。建议映射：suggestions 条数==marks 条数按序一一对应，否则按 wrong===mark 文本匹配（每条只用一次），都匹配不到则该处无 title。面板预览＝顶部「共发现 N 处错别字：1. X → Y」清单 + `---` + 带 span 的全文（纯文本渲染、span 以源码可见属预期），确认后 `setChapterBody` 全量覆盖。max_tokens 取 `max(cfg.max_tokens, ceil(正文长×2)+1024)` 保证回显预算。

- **`export-ai-prompts`（导出AI提示词，确定性无 LLM）**：弹出功能点选择弹窗（checkbox 列表 + 全选/全不选；**整行可点**——点击行内任意位置含 checkbox/文字/说明区即切换该行选中态，键盘空格同路径），用户勾选后只导出选中功能点对应文件（未勾选的完全跳过、不写入任何条目），「AI提示词（导出说明）」元数据条目始终包含不参与选择。把上述全部 AI 阶段（章域 8 + 大纲域 6 + 摘要域 3）在当前小说盘上数据下**会实发的 system/user 提示词**逐节导出到书根《AI提示词/》子目录各独立 `.md` 文件（`manager.savePromptExportDocs`，案头资料、重复导出整体覆盖），供逐个喂本地模型比对输出。行为约定：①导出全程零 LLM 调用，与各 cmdXxx 复用同一构建函数与参数；②弹窗输入取默认基准——文本弹窗留空、章数弹窗 `defaultCount=max(现有章数,1)`（文档头部集中声明此口径）；③按盘上现状判定「现在会不会触发」，不会触发的阶段只写跳过原因（`exportSkipSection`），例如去AI味无命中、AI 拆章在章标记已存在时不触发、摘要已新鲜时延迟生成不再调用——唯一例外 /write：激活章已有正文时运行时不触发，但仍照常组装导出提示词（节内备注「假设触发时实发」），便于随时调试不必切空章；④增量链（卷设计→逐章、AI 拆章逐章、analyze-cast 逐章、书级大纲续写）只导出首步，依赖前一步输出处用占位符注明；⑤每节标注模型配置来源（阶段映射 vs 全局激活 + cfg.name/model_name）与运行时显式参数覆盖；⑥章域基准=写字台当前激活章（无选择器）、大纲/卷摘要域基准=当前卷；⑦不触发任何写盘副作用（不调 `ensurePlanningGuide`、不生成摘要），只读判定——写作上下文中的摘要同样不触发延迟生成：已存新鲜摘要照放、缺失处填占位符「（此处有摘要，尚未生成）」（无成员章摘要的卷运行时也跳过、不占槽，故不填）。实现：`cmdExportPrompts`/`buildPromptExportDoc(story, selectedFeatures?)`（selectedFeatures 为空时导出全部向后兼容，非空时 trySec 内未命中则 return 跳过；每节 `trySec` 独立 try/catch 保证单节失败不拖垮整篇、`fenceBlock` 按内容反引号自动升级围栏），见 [command-reference.md](./command-reference.md)。
