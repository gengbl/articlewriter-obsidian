## 通用约定

- 统一「submitted/resolved 标志」模式：先置位再 `close()`，`onClose` 里未提交才触发 onCancel，防止 Esc 与按钮双触发。新 Modal 必须照抄该模式。
- **styles.css 禁用 `:has()` 选择器**（外部检查器告警：大范围选择器失效、性能隐患）——「子元素存在 → 父/兄弟样式」一律改由视图在渲染时挂显式类（先例：时间线 done 行 `is-tl-done-row`）。
- **预填字段的状态变量必须从传入的初始值初始化**（v0.4.4+ 修 EventEditModal 回归时定下的约定）：Obsidian 控件 `setValue()` **不触发 `onChange()`**，若局部变量只靠 onChange 回填、就恒拿不到未触碰字段的值——保存时校验必失败（弹窗关不上）或把既有内容写成空串。写法＝`let x = (initial?.x ?? 默认值)`，onChange 只负责「改动之后」的值。无预填的创建型弹窗（如 NewStoryModal）不受此约束。
- **统一基类 `AwModal`（v0.4.3+，`src/modals.ts` 导出）**：本插件所有 `extends Modal` 的弹窗一律 `extends AwModal`（modals.ts 19 个 + main.ts `StatusModal`；`SuggestModal`/`FuzzySuggestModal` 系列不是表单、保持原样）。基类构造函数给 `contentEl` 挂 `.aw-form` 作用域类——**挂在构造函数而非 `onOpen`**：现有子类普遍覆写 `onOpen` 且不调用 `super.onOpen()`，构造期挂类对全部子类恒生效。新写弹窗直接继承 `AwModal`，不要再用裸 `Modal`（main.ts 的 obsidian import 已移除 `Modal`）。CSS 口径见 [l3-settings-page.md](./l3-settings-page.md)「统一表单布局」。**v0.4.11+ 基类同时在 `modalEl` 挂 `.aw-modal`**＝弹窗根元素作用域类（CSS 无法从 contentEl 向上选，手机端弹窗修正需要选中弹窗本体；符合上文「禁 `:has()`、改挂显式类」约定）。**v0.4.11+ 基类两个按钮行助手**：`addButtonsRow()`＝底部动作按钮行（`new Setting()`＋挂 `.aw-btns-right`＝隐藏空标签列＋control flex-end＋margin 归零），24 处调用点统一走它；`addSaveCancelRow(onSave)`＝其固定搭配「保存(CTA)／取消」（`AddCharacterModal`〔此前只有「确定」＝缺取消入口〕与 `RelationshipModal`〔原「确定/取消」〕共用，文案口径＝**编辑/表单类弹窗一律「保存／取消」**（用户要求）；取消＝`close()`→`onClose()`→`submitted=false`→调用方 `onCancel`）。旧的自定义 div `.aw-addchar-actions` 已废弃（CSS 里只留一条废弃说明）。创建/确认类弹窗仍按语义用「创建」「确定创建」「确认」等，单字段输入弹窗（`TextInputModal`/`TextAreaPrompt`）保持「确定」。
- **手机端弹窗＝完整恢复 PC 排布（v0.4.11+ 用户两轮反馈：第一轮「不必占满高度」不够，第二轮明确＝和 PC 端一样、检查所有弹窗）**：手机版核心（实测本机 Obsidian 包内 CSS）对本插件弹窗做两件事——①`.is-phone .modal-content` 强制 flex 纵向列＋吃 `flex:1 1 auto` 撑满弹窗高；②普通 Setting 行（`:not(:is(.mod-toggle,.mod-navigable,.mod-action,.setting-item-heading))`，深至〔0,5,0〕）强制 `flex-direction:column`（标签上/控件下）且控件/input/button 一律 `width:100%`——每行数倍变高、整窗铺满屏幕＝用户看到的「沿高度平均分布」。**只挡①不挡②仍显占屏**（第一轮教训）。修正＝styles.css `is-phone` 段对**所有本插件弹窗**（`.aw-modal`＝AwModal 构造期挂 modalEl，27 个全覆盖；SuggestModal 搜索窗＝核心 prompt 形态不处理）：弹窗 `height:auto`＋内容层 `flex:0 1 auto;justify-content:flex-start`（内容决定弹窗高，上限核心 `--dialog-max-height`）＋全部后代行 `flex:0 0 auto`＋`gap` 收紧＋行 `flex-direction:row`＋控件列 `width:auto;flex:1 1 auto`（沿用桌面 `.aw-form` 吃剩余宽口径）＋按钮 `width:auto`。特异性对核心逐条压过或打平后靠插件 CSS 后加载取胜（行〔0,5,0〕＞核心〔0,4,0〕、控件列〔0,6,0〕＞〔0,5,0〕、按钮〔0,4,1〕打平）。mod-toggle/navigable/action/heading 行沿用核心原样（本就 row）。桌面零影响（`is-phone` 仅手机；平板 `is-tablet` 核心不做此改造）。**设置页同口径但另写一段**：本插件设置在核心 `.modal.mod-settings` 的 `.setting-group > .setting-items` 里（不是 `.aw-modal`），`getSettingDefinitions()` 里容器同时挂 `.aw-form`＋`.aw-settings-form`。核心手机版把设置行做高的四条规则（逐条从安装包 `obsidian.asar` 内 CSS 核对）：①行 `gap:16px`＋`padding:16px`＋`margin-bottom:8px`；②行 `flex-direction:column`（标签上/控件下）；③控件列 `width:100%`；④**控件列内 input/select/.combobox-button/button 一律 `width:100%;margin:0` ＋ `button{padding:10px}`**——④ 才是「纵向拉伸」最大元凶（tab 页头、模型配置列表操作钮、引用文档增删钮＝每人独占一整行）。styles.css `.is-phone .aw-settings-form` 段逐条反打：行 `flex-direction:row;align-items:center`＋padding/gap 收紧、控件列 `width:auto;flex:1 1 auto`（输入框仍 `width:100%` 撑满控件列）、按钮 `width:auto`＋padding/height 复位到桌面核心基线（`var(--size-4-1) var(--size-4-3)`／`var(--input-height)`／`var(--font-ui-small)`）。⚠️ 两个坑位：(a) 想靠「复位 `flex:0 0 auto`」阻止拉伸＝**空转**（`.setting-items` 是块级、行不是 flex 项，v0.4.11+ 第一版就是这么错的）；(b) `.is-phone` 之外还有一条同效果的**容器查询** `@container (max-width:400px){.setting-item:not(:is(…,.mod-list *)){flex-direction:column}…}`（容器＝`.vertical-tab-content{container-type:inline-size}`；声明式 `type:"group"` 的组**不会**挂 `mod-list`，只有 `type:"list"` 才挂，所以它确实打在我们行上）——注意这条族**与设备无关**：容器＝`.vertical-tab-content{container-type:inline-size}`（设置页滚动容器），`getSettingDefinitions()` 的 `containerEl` 就是核心 `setting-page-content` div，**PC 上把设置页窗口拖窄／分屏（宽 ≤400px）同样命中**＝只挂 `.is-phone` 前缀的反打规则在这种场景全部不生效（v0.4.11+ 就是这样漏掉的，故新增 `.setting-page-content.aw-form.aw-settings-form …`〔0,5,0〕/〔0,5,1〕这条与设备无关的段）。附带核实：核心 `container-type` 只挂在 `.vertical-tab-content`/`.horizontal-tab-content`（＋empty-state/tab-header/metadata 具名容器），**`.modal-content` 没有 container-type＝弹窗内不受这条族影响**；声明式 `type:"group"` 的组**不会**挂 `mod-list`（只有 `type:"list"` 才挂），所以它确实打在本插件设置行上。另：弹窗内列表/正文容器的 vh 上限（`.aw-action-list` 60vh／`.aw-panel-body` 65vh／`.aw-fixrefs-review` 55vh）是 PC 防超屏用的，手机上与核心 `--dialog-max-height` 构成双重限高＝styles.css 里 `.is-phone .aw-modal` 段把内层 `max-height` 放开，交给弹窗外层滚动；`.aw-btns-right` 组内按钮加 `flex:0 0 auto`＝任何「width:100%」口径（核心窄容器／手机）都拉不开底部按钮行。平板（`is-tablet`）核心**不做** Setting 行 column 改造（已核：只有按钮 padding、导航项圆角等 13 条），无需额外处理。特异性口径：本段行〔0,6,0〕＞核心〔0,5,0〕；按钮/控件 width 本段〔0,5,1〕＞核心〔0,4,1〕；按钮 padding/height 本段〔0,3,1〕＞核心〔0,3,0〕。另：自定义行（LLM 配置／写作阶段）的定宽标签列（`.aw-llm-label{flex:0 0 220px}`）在窄屏会吃掉大半行宽，另加 `.is-phone
