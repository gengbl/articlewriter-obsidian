# L3 · 创作规范三层与汇总文件生命周期

## 创作规范三层结构

- **创作规范三层结构**（优先级降序）：①小说级 `<书名>/WRITING_GUIDE.md` > ②用户级 `<work_dir>/WRITING_GUIDE.md` > ③系统级 **插件数据目录文件** `.obsidian/plugins/articlewriter/WRITING_GUIDE.md`（首启由 data.json 内嵌值或内置默认播种，见 `src/system_guide_default.ts`；读不到回落内置默认）。系统级路径**固定、非用户可配**——原 `llm.system_guide_path`（vault 相对路径覆盖）设置项已移除，data.json 的 `system_guide` 仅作一次性迁移种子：`ensureSystemGuideFile`（main.ts）播种文件后调 `purgeLegacySystemGuideFields` 把 `system_guide`/`system_guide_path` 从 data.json 删除落盘（v0.2.25+，data.json 不再存指南正文；张力规则/禁用词播种文件同模式、从未入 data.json）。view：各层直接打开对应文件，仅一层直开 / 多层弹选择器 / 全无则提示「用编辑创建」；edit 选层后全量保存（缺失新建 / 存在覆盖），任一层变更后刷新该书《写作指南汇总》。**每书聚合文件 `<书名>/写作指南汇总.md`** = 三层按类目合并落盘（mergeGuideCategories 块级分组 + serializeAggregateGuide + agg-hash md5 变更检测头），**v0.2.24+ prompt_files 装配改造后仅作用户查看产物、不再进提示词**——LLM 写作命令、对话与大纲生成/AI 拆章注入的【创作规范】＝三层指南原文经 `loadWriterGuides`→`assembleGuideTexts`（main.ts:2421）直接装配的 `guideCleanText`（见 [l3-prompt-assembly.md](./l3-prompt-assembly.md)；大纲路径经 `assembleVolOutlineContext` specs 在【书籍信息】后插【创作规范 · …（生成大纲时必须遵循、不得违背）】块，旧 VolOutlineGenInput/BookOutlineGenInput `guideText?` 字段退役）。**合并语义（块级分组）**：通用/禁用词先经 `splitGuideBlocks` 把各层分类文本拆成块（遇「级别 ≤ 当前块级别」的标题开新块、更深子标题留在父块内、首个标题前内容归前言块 (0,"")、代码围栏内 # 行不当标题），再按「标题级别＋标题文本」把跨层同名小节归为一节——节内按优先级（书级→用户级→系统级）依次拼接各行并逐行去重，节序按优先级首次出现排列；**「作者身份」节置顶**——标题含「作者身份」的节在通用类内一律抬到最前（多个同名节保持相对顺序；它通常只在系统层存在，按首现排列会落到全部书/用户层节之后，用户误以为没注入提示词），agg-hash `v` 随之 bump 至 3 强制旧汇总重建一次；**每类别独立去重集**（曾共用一个 seen 致用户层禁用词骨架标题吞掉系统层通用同名标题、正文失去小节结构）；故事风格/个人特色取最高优先级有内容的层。仅当三层任一 md5 或合并算法版本 v 变化才重算——检测更新重建由写作命令、对话与五个大纲生成/AI 拆分入口〔vol-outline-generate · 无卷兜底批量 · book-outline-generate · book-outline-to-volumes · AI 兜底逐章拆分〕的 `loadWriterGuides` 调用触发（批量循环整批只查一次）。**空指示段自动注释**：序列化前各分类经 `commentOutEmptySections`——标题下到下一同级/更高级标题间无任何内容行的小节整体包进 HTML 注释（围栏内 # 不当标题、水平线不算内容；父节为空时含嵌套子标题一次成块，相邻空段合并一片），上方加一条提示注释引导用户回 WRITING_GUIDE.md 填写；因注入串（guideCleanText）剥全部注释，这些段落不参与提示词生成（变换是三层输入的确定函数，不破坏 agg-hash 幂等）。

- **「类型要点」独立文件（v0.2.x+）**：原系统指南「## 十一、不同类型写作要点」拆为 4 个独立文件，唯一来源 docs/guide-types/*.md（esbuild `.md=text` 打包），首启由 `ensureGuideTypeFiles()`（onStartup 调用）播种到插件数据目录 `.obsidian/plugins/<id>/guide-types/<key>.md`（缺失才写、已存在不覆盖——用户可编辑定制；失败仅 console.warn 不阻断启动）。读取走 `readGuideTypeText(key)`：读不到/为空回落内置默认（提示词永不缺类型规范）。汇总管线 `persistAggregatedGuide(story, bookText, userText, systemText, genre)` 按故事状态 `genre` 自由文本经 `matchGuideTypes`（src/guide_types_default.ts GUIDE_TYPES 关键词正则，可多命中）匹配，命中的每个类型以「## 写作要点（<name>）」+ stripComments(类型文件).trim() 追加进合并结果「通用」类目；未命中→不注入（**v0.2.24+ 注**：汇总管线只维护查看产物；提示词里的类型要点改由 `assembleGuideTexts` specs 的 `guide-types/<key>.md` file 条目直装——transform 加「## 写作要点（name）」前缀、fallback 内置 defaultText，见 [l3-prompt-assembly.md](./l3-prompt-assembly.md)）。agg-hash 头新增 `t=` 字段 = md5(类型要点拼接文本)（无命中为空串），旧汇总头无 t → parseAggHash 按 "" 处理 → 一次性重建。「重新生成系统写作指南」（cmdRegenerateSystemGuide）一并覆盖重置这 4 个文件。**迁移注意**：已播种的旧系统级指南仍含完整第十一节（会作为「通用」继续注入、与新组装的类型要点重复），不做自动剥离——升级用户需跑一次该命令消除重复。对话面板「无当前小说」分支无题材上下文，保持 user+system 两层合并、不落盘、不注入类型要点。
