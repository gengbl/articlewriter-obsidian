# L3 · 摘要管线与写作上下文

## 卷摘要

- **卷摘要 `<volDir>/卷摘要.md`（v0.0.15+）**：本卷滚动级情节摘要，格式对齐《章节摘要.md》——H1 标题 + `<!-- 内容哈希：<md5> -->` 校验头 + 纯文本正文。**哈希语义**（v0.1.4+）：各「已有且未过期《章节摘要》」的成员章按阅读序拼 `"key|md5(摘要)"` 再取 md5（`computeVolumeDigest`）——与生成输入完全一致；旧版基于正文 md5 的文件首次使用必然失配→自愈重建一次。**生成方式**：非用户手填、**纯延迟生成**——上下文组装需要时经 manager.ensureFreshVolumeSummary 以收集到的章节摘要为输入整体重建并落盘（详见下方 v0.1.4+ 条③）；写盘命令保存后不再做任何 eager 更新；`use_summaries: false` 时跳过。读取侧 loadWritingData 既用它注入本卷【卷摘要】块，也用于跨卷缺口填充（两者均仅当设置 `includeVolumeSummary` 开启时生效、默认关——见下方 v0.1.4+ 条①）。

## 三层写作上下文结构（v0.0.15+）

- **三层写作上下文结构（v0.0.15+）**：buildWritingContext 输出分三节——`== 故事情况 · 书籍级 ==`（全书大纲/书籍角色设定/书籍场景/【人物关系·书】）、`== 故事情况 · 卷级（<卷名>） ==`（本卷大纲/卷摘要/本卷人物关系/本卷角色设定/本卷场景，仅当前章在卷内出现）、`== 故事情况 · 章级（…第N章） ==`（本章目录文档原文 folderDocs + 【本章人物关系】），末尾伏笔提示。**去重规则**：①结构化角色/场景列表按「所属容器」分层（c.vol===activeVolId→卷层，否则书层），并排除归属当前章的条目（excludeCharNames/excludeSceneIds，其完整信息已由章层 folderDocs 原文承载）；②人物关系三份清洗文本逐行跨层去重（dedupeLinesAgainst，优先级 章 > 卷 > 书，normalizeRelLine 归一化前缀符号与空白后比较）。folderDocs 已剔除《人物关系.md》改经 chapterRelationships 单独传入。

## v0.1.4+ 写作上下文窗口、摘要自动生成与角色范围收窄

- **v0.1.4+ 写作上下文窗口、摘要自动生成与角色范围收窄**：①前文窗口章数 N=data.json 顶层键 `prevChapters`（设置页「前文参考章数 prevN」，空/非法=内置默认 3，0=不注入前文；main.ts effectivePrevN() 实时读取、StoryManagerOptions.getPrevChapters 注入 manager）。**卷模式窗口限本容器**——loadWritingData 从阅读序取最近 N 个候选时跳过落在其他容器的头部（startIdx while 推进至首个同卷成员）；本卷内不足 N 章时以阅读序在前各前卷的《卷摘要.md》由近及远补足至 N（input.prevVolSummaries → buildWritingContext 在【前文内容】之前渲染为【前卷摘要 · <卷名>】块，use_summaries=false、prevN=0 **或设置 includeVolumeSummary 关闭（默认）**时不填充；某前卷摘要缺失/过期时经同一 ensure* 入口延迟重建，不再静默为空）；平面/混合的书根章节保持原阅读序窗口不变。**`includeVolumeSummary` 开关（data.json `settings.includeVolumeSummary`，设置页「注入整卷《卷摘要》」，默认关）**：关闭时严格只按 prevN 注入单章摘要——本卷【卷摘要】与跨卷【前卷摘要】均不注入、也不触发卷摘要 LLM 重建；开启才恢复三层上下文的卷级 digest 行为。**【前文内容】标题与遍历区间按实际收录章节的 min/max ordinal**（跨卷限制/空章造成缺口时缺位自动跳过，全无则整块省略）。②窗口章无正文时回落《章节大纲.md》清洗文本作来源（story_manager.chapterSummarySource「有效来源」=正文||大纲；预览即该来源文本）。缺失/过期章节摘要经 StoryManagerOptions.generateChapterSummary 注入的 LLM **自动生成并落盘**（ensureFreshChapterSummary：提示词 = prompts.ts CHAPTER_SUMMARY_SYSTEM_PROMPT + buildChapterSummaryPrompt(viaOutline 时在「章节：」行标注「暂无正文，依据本章大纲概括」)，max_tokens=600 temperature=0.4；失败/未配置返回空串→回退原文预览不阻断）。**哈希语义变更**：《章节摘要.md》存 hash 改对 md5(有效来源)校验——旧文件有正文者仍等于 md5(正文)、完全兼容；空正文+有大纲者此前从不生成、现按纲生成。includeCurrentSummary 路径（/continue /rewrite /polish 等）同覆盖当前章。③**摘要全部延迟生成、需要时再生成**：写盘命令（/write /continue /rewrite /polish /deai）保存后不再触发任何 LLM 工作；上下文组装（loadWritingData，各写作命令与状态快照共用入口）需要窗口章/前卷/本卷摘要时才经 manager.ensure* 按需触发。**卷摘要 = 以该卷中已有且未过期的成员章《章节摘要》为输入的整体重建**（ensureFreshVolumeSummary **只读收集**——不主动触发其他章节的 LLM 生成，缺失/过期者跳过、待其进入前文窗口时按需自生，避免每次重建遍历全卷逐个生成；→ prompts.buildVolRebuildPrompt/VOL_SUMMARY_SYSTEM_PROMPT，max_tokens=900 temp=0.4；随更多章节摘要陆续生成而变全；取代 v0.0.15「最新章节增量合并」滚动法——多轮有损压缩会丢失早期章节信息）。卷摘要指纹口径同步变更：md5(各成员章「key|md5(已存且新鲜的章节摘要)」按阅读序拼接)，与生成输入完全一致；旧版基于正文 md5 的文件首次使用必然失配→自愈重建一次。**v0.2.0+ `loadWritingData` 增 `opts.ensureSummaries`（默认 true）**：只读展示场景必须传 `false`——为 `false` 时窗口章摘要退化为 `readFreshSummary`、卷摘要退化为 `readFreshVolumeSummary`（均只读已有新鲜摘要、缺失即留空），**绝不触发 LLM**；`main.ts getChatSystemPrompt()`（LLM 对话框提示词与「提示词约 Nk 字」标签）传 `false`，否则切书/切章（`notifyContextChanged` 每次状态变更都会刷该标签）会凭空弹「生成过程」面板并开始输出摘要，用户视角就是"自动开始写"。写作命令（/write /continue /rewrite /polish /review）保持默认 true。生成工作过程经 StoryManagerOptions.onProgress **统一「生成过程」面板实时展示**（main.ts notifyGenProgress 驱动 GenProgressView ItemView：每个 LLM 任务追加一行带时间戳日志并自动滚底、onProgress(null)=本轮结束追加分隔完成行；打不开仅告警不影响生成本身）——该面板与写作命令的章节流式预览为同一实例（v0.1.4+ 起替换原独立 StreamingPreviewModal）：摘要阶段完成后 beginWritingPanel 在同面板内继续展示章节正文打字机效果与「保存/不保存」决定，失败均按无摘要降级不阻断。**并发竞态防护**：manager.genInFlight 以「书|章/卷」键缓存在途生成 Promise——写作命令预览与聊天面板快照等多个 loadWritingData 入口交错并发时共享同一任务，同章/同卷绝不重复发起 LLM；任务结束即出缓存，后续组装仍走正常哈希门控。④写作上下文角色范围收窄（loadWritingData filter，仅影响 data.characters、StatusView 等直调 loadAllCharacters 处不变）：书根《人物.md》条目恒含；写卷内时排除书根区章节级条目；本卷全量保留；他卷仅取其卷级《人物.md》条目（chapter=0）且仅限阅读序在前者（未来卷不注入、绝不深入他卷各章《人物.md》）。场景注入维持原 mention-driven 行为不变。
