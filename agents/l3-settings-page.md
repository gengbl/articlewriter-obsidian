# L3 · 设置页与 LLM 配置实现细节

设置页与 LLM 配置模块的实现级说明（源文件职责：调用层 / 类型与默认模板 / 设置页声明式实现）；模块级行为见 [l2-settings-llm-config.md](./l2-settings-llm-config.md)。

## 相关源文件

| `src/llm_client.ts` | LLM 调用层（openai SDK v7，esbuild 打包进 bundle）：`normalizeBaseURL`（base_url 未含 /vN 自动补 /v1）+ `createClient`（无 api_key 时用占位值过 SDK 校验，本地服务忽略该头）+ `testConnection`（GET /models）+ `chatCompletion`/`chatStream`（流式逐块回调，可选 `onReasoning` 第 6 参透出思考型模型 `delta.reasoning_content` 增量；正文空而思考非空时按 finish_reason 抛针对性报错——`length`=思考与正文共享 max_tokens 预算被思考耗尽（建议调大 max_tokens/降 reasoning_effort/关思考），否则=思考块未正常闭合；文案刻意不含「输出为空/未返回内容」以免调用方盲目重试）。buildParams 含已知端点上限保护：base_url 匹配 api.deepseek.com 时 max_tokens 夹取到 393216（384K，V4 时代官方上限）——旧 V3/R1 时代的 8192 对默认开思考的 deepseek-flash 是致命的（思考耗尽整个预算→正文恒空，即 DeepSeek「无法响应」根因，2026-10 修复）。思考模式开关 cfg.thinking（设置页「思考模式 thinking」，on/off）仅当 base_url 或模型名含 deepseek 时发送为 DeepSeek 官方字段 `thinking:{type:"enabled"|"disabled"}`（off/disabled/false/no/0→disabled，其余非空值→enabled；OpenAI 官方等端点对未知字段会 400 故不透传，留空=跟随服务端默认——deepseek-flash 默认开思考）。配置级采样参数统一由 `samplingExtras(cfg)` 注入 buildParams（先于 extra 合并、调用方显式 extra 可覆盖）：顶层 `reasoning_effort` 随每次请求发送——DeepSeek V4 原生支持（none/low/high/max，minimal→low、medium/xhigh→high 兼容映射；与 thinking:{type} 同发时后者优先选模式、不冲突不 400），OpenAI o 系列原生支持，llama-server + Qwen jinja 模板实测 "none" 关思考/"high" 注入 xhigh 推理指令，vLLM 识别并自动转 enable_thinking，其余兼容端点忽略未知字段无副作用。**本地端点大纲/长文生成失败根因（2026-11 修复）**：思考型本地模型默认开思考且思考与正文共享 max_tokens 预算——插件此前从不发送任何思考控制，思考耗尽预算致 content 恒空（表现为「思考型模型正文为空」）；修复=buildParams 接入 samplingExtras 使配置里的 reasoning_effort 真正生效，用户侧在设置页把 local 配置 reasoning_effort 设为 none（或调大 max_tokens）。openai_extras 为声明式参数名名单（对齐 Python llm_client.py 语义）："repeat_penalty" → 发送 cfg.repeat_penalty **数值**（llamacpp 私有参数，仅显式声明才发，避免远程端点 400）；其余名字按布尔 true 透传（声明式开关兜底）——旧实现 `ex[k]=true` 一律发布尔值是 bug，已修。配置来源=插件 data.json 中 active_llm 指向的配置。注意 openai v7 类型走 `OpenAI.Xxx` 命名空间导入，流式 create 需显式断言 `ChatCompletionCreateParamsStreaming` 重载。buildParams 返回本地接口 `LlmChatBody`（含 `[k:string]:unknown` 索引签名以透传 openai_extras、`model?:string` 允许本地服务留空）而非 `as any`——新增请求体字段要么在接口里声明、要么靠该签名兜底，勿回退到 any。`describeLlmError` 错误诊断：**v0.2.x+ 上下文窗口溢出识别**——错误文案匹配 `/exceeds the available context size|maximum context length|context length exceeded|prompt is too long|too many tokens/i`（llama-server / vLLM / OpenAI 等对超 ctx 请求直接 4xx 拒绝、不可重试）时追加三条可操作出路〔①换上下文窗口更大的端点/模型 ②调大服务端上下文（如 llama-server --ctx-size 131072，内存代价随之增长）③减少注入内容（降低目标章数 / 用「继续生成」而非完整生成 / 精简策划指南与写作指南）〕；文案刻意不含「输出为空」「未返回内容」（streamOnce 依赖这两个串判定空结果重试） |
| `src/plugin_config.ts` | LLM 配置类型与默认模板：`LlmConfigDoc` + `PluginConfig`（active_llm/llm_configs/system_prompt/desc_style/system_guide）+ `buildDefaultLlmConf()`（首次运行预置 local/deepseek/qwen-dashscope 三组标准模板，api_key/model_name 留空待填；local 条目单独覆盖 `reasoning_effort:"none"`——本地 llama-server + Qwen 等模板默认开思考，"high" 会耗尽 max_tokens 预算致正文恒空，新装防坑；deepseek/qwen 条目沿用 base 的 "high"。注意：仅影响**新装**首启播种，已有 data.json 的存量配置不受影响，须用户在设置页自行改；`system_guide`/`system_guide_path` 为历史遗留字段——系统级写作指南已迁至插件数据目录文件 `WRITING_GUIDE.md`，data.json 内嵌值仅作首启一次性迁移种子、运行时不再读取，设置页对应行亦已移除）。载体为 Obsidian 标准插件数据目录 `data.json`（saveData/loadData），不再使用 MD 文件 |
| `src/main.ts`（设置页部分） | **设置页为声明式单实现** `getSettingDefinitions()`+`getControlValue/setControlValue`；因该 API @since 1.13.0、`fileManager.trashFile` @since 1.6.6，v0.0.7 起 manifest minAppVersion 由 1.4.0→**1.13.0**（社区插件目录校验规则 obsidianmd/no-unsupported-api 的硬性要求）——当前 manifest 下框架恒走声明式路径；pre-1.13 的已废弃 `display()/renderLlm()` 渲染路径已删除（校验器禁 deprecated API，勿再引入；连带移除 llmSelName 状态与孤儿 Setting import）。key 约定：顶层 `workDir`/`autoOpenOnCreate`/`prevChapters`(v0.1.4+ 前文参考章数 N，留空=默认 3)；全局 `llm.active_llm`/`system_prompt`/`desc_style`（系统级写作指南路径**固定**为插件数据目录文件，非用户可配——原 `llm.system_guide_path` 设置行已移除）；每份配置 `cfg.<数组下标>.<field>`（用下标而非 name 避免解析歧义，增删/重排后靠 `update()` 重建）。模型配置渲染为 list+子页（支持新建 config-N/删除[激活项被删则回落第一个]/拖拽重排 + 每页「设为激活」「测试连接」动作行）；数值字段 temperature/max_tokens 仍用 text 控件在 setControlValue 里 parse（空=undefined，对齐旧 UI，不用 number 控件以免空值被强转 0）。**v0.2.21+ 多值字段改下拉框**：`reasoning_effort`/`thinking` 由 text 改为 `type:"dropdown"`（与 `llm.active_llm`/`llm.desc_style` 同形状 `{key,type,options:Record<string,string>}`），选项集＝effort：`""`留空（不发送）/none（关思考）/low/medium/high/max；thinking：`""`留空（跟随服务端默认）/on（开思考）/off（关思考）；**存量值防丢失**——当前值不在标准集时经 `Object.prototype.hasOwnProperty.call` 检查动态并入选项并标「（存量值）」，避免用户已填的非标值在下拉框中不可见/被清空。getControlValue/setControlValue 的 `cfg.*` 分支天然兼容字符串值（返回 `String(v)` 或 ""、写入 `rec[field]=str.trim()||undefined`），未改动 |
