# L3 · 设置页与 LLM 配置实现细节

设置页与 LLM 配置模块的实现级说明（源文件职责：调用层 / 类型与默认模板 / 设置页声明式实现）；模块级行为见 [l2-settings-llm-config.md](./l2-settings-llm-config.md)。

| `src/llm_client.ts` | LLM 调用层（openai SDK v7，esbuild 打包进 bundle）：`normalizeBaseURL`（base_url 未含 /vN 自动补 /v1）+ `createClient`（无 api_key 时用占位值过 SDK 校验，本地服务忽略该头）+ `testConnection`（GET /models）+ reasoning_effort/关思考），否则=思考块未正常闭合；文案刻意不含「输出为空/未返回内容」以免调用方盲目重试）。buildParams 含已知端点上限保护：base_url 匹配 api.deepseek.com 时 max_tokens 夹取到 393216（384K，V4 时代官方上限）——旧 V3/R1 时代的 8192 对默认开思考的 deepseek-flash `thinking:{type:"enabled"|"disabled"}`（off/disabled/false/no/0→disabled，其余非空值→enabled；OpenAI 官方等端点对未知字段会 400 故不透传，留空=跟随服务端默认——deepseek-flash 默认开思考）。配置级采样参数统一由 `samplingExtras(cfg)` 注入 buildParams（先于 extra 合并、调用方显式 extra 可覆盖）：顶层 `reasoning_effort` 随每次请求发送——DeepSeek V4 原生支持（none/low/high/max，minimal→low、medium/xhigh→high 兼容映射；与 thinking:{type} 同发时后者优先选模式、不冲突不 400），OpenAI o 系列原生支持，llama-server + Qwen jinja 模板实测 "none" 关思考/"high" 注入 xhigh 推理指令，vLLM 识别并自动转 enable_thinking，其余兼容端点忽略未知字段无副作用。**本地端点大纲/长文生成失败根因（2026-11 修复）**：思考型本地模型默认开思考且思考与正文共享 max_tokens 预算——插件此前从不发送任何思考控制，思考耗尽预算致 content 恒空（表现为「思考型模型正文为空」）；修复=buildParams 接入 samplingExtras 使配置里的 reasoning_effort 真正生效，用户侧在设置页把 local 配置 reasoning_effort 设为 none（或调大 max_tokens）。openai_extras 为声明式参数名名单（对齐 Python llm_client.py 语义）："repeat_penalty" → 发送 cfg.repeat_penalty **数值**（llamacpp 私有参数，仅显式声明才发，避免远程端点 400）；其余名字按布尔 true 透传（声明式开关兜底）——旧实现 `ex[k]=true` 一律发布尔值是 bug，已修。配置来源=v0.2.22+ 各 LLM 命令按所属写作阶段经 `getPhaseLlmSetup(phaseIndex)` 取模型（该阶段 `llm_config_name` → 未指定回落第一个配置 `cfgs[0]`；对话框 `chat_model` 与旧版激活态 `active_llm` 均不参与阶段回退），连接测试走阶段 3 编写文章配置。注意 openai v7 类型走 `OpenAI.Xxx` 命名空间导入，流式 create 需显式断言 `ChatCompletionCreateParamsStreaming` 重载。buildParams 返回本地接口 `LlmChatBody`（含 `[k:string]:unknown` 索引签名以透传 openai_extras、`model?:string` 允许本地服务留空）而非 `as any`——新增请求体字段要么在接口里声明、要么靠该签名兜底，勿回退到 any。`describeLlmError` 错误诊断：**v0.2.x+ 上下文窗口溢出识别**——错误文案匹配 `/exceeds the available context size|maximum context length|context length exceeded|prompt is too long|too many tokens/i`（llama-server / vLLM | `src/plugin_config.ts` | LLM 配置类型与默认模板：`LlmConfigDoc` + `PluginConfig`（active_llm/llm_configs/system_prompt/desc_style/system_guide）+ `buildDefaultLlmConf()`（首次运行预置 local/deepseek/qwen-dashscope 三组标准模板，api_key/model_name 留空待填；local 条目单独覆盖 `reasoning_effort:"none"`——本地 llama-server + Qwen 等模板默认开思考，"high" 会耗尽 max_tokens 预算致正文恒空，新装防坑；deepseek/qwen 条目沿用 base 的 "high"。注意：仅影响**新装**首启播种，已有 data.json 的存量配置不受影响，须用户在设置页自行改；`system_guide`/`system_guide_path` 为遗留字段——系统级写作指南已迁至插件数据目录文件 `WRITING_GUIDE.md`，data.json 内嵌值仅作首启一次性迁移种子、运行时不再读取，设置页对应行亦已移除；v0.2.25+ 起 `ensureSystemGuideFile` 播种后调 `purgeLegacySystemGuideFields` 把两字段从 data.json 删除落盘，loadSettings 亦不再向 data.json 回填指南正文）。载体为 Obsidian 标准插件数据目录 `data.json`（saveData/loadData），不再使用 MD 文件。**v0.2.25+ 引用文档配置框**：`WritingPhase.ref_docs?: string[]`——本阶段装配实际注入的引用文档清单，条目 = 内置文档 key 或 `file:<vault 路径>`；`undefined`=该阶段默认清单（不做 loadSettings 回填）、`[]`=只注入锁定写作指南。配套导出：`REF_DOC_LABELS`（15 个内置 key 的显示名）、`PHASE_REF_DOC_CATALOGS: Record<string,string>[]`（各阶段 0–3 可添加的内置文档目录，设置页下拉候选按阶段裁剪）、`PHASE_REF_DOC_DEFAULTS: string[][]`（各阶段默认清单） |
