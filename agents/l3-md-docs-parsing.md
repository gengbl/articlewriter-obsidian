## 格式条款

- **《人物关系.md》条目格式（v0.1.9+，书/卷/章三层通用；模板见 story_types.ts `CHAPTER_RELATIONSHIPS_TEMPLATE`〔亦用于书籍级〕/`VOL_RELATIONSHIPS_TEMPLATE`）**：纯 Markdown 段落（**不是 frontmatter**）——`## 角色A - 角色B` 标题 + 字段行 `- 类型：` / `- 状态：` / `- 描述：`。描述可跟同字段行正文、```text 围栏内容或块内自由文本行（三者合并）；状态建议 active（进行中）/ pending（铺垫中）/ ended（已结束），也接受中文说法。**同一份原文两处消费、互不干扰**：人物关系面板走 `md_docs.parseRelationships` 结构化展示（书根取书级文件、卷/章按 current_volume / current_chapter 定位）；写作上下文仍按 `cleanRelationshipsDoc` **原样整块注入**提示词，不做结构化改写。**向后兼容**：旧写法（标题带角色对 + ```text 描述围栏、无类型/状态）照常解析，面板显示「未标注类型/状态」；角色名不写在标题里时可用字段式 `## 关系1` + `- 角色1：` / `- 角色2：`（角色对都解析不出的块整块丢弃，不误当关系）。自建/自定义关系文档无需登记，面板按文件名 `人物关系.md` 三层聚合并着色。**程序化写入入口（v0.2.0+）**：`manager.appendRelationships(story, scope, entries, { volId?, chapterKey? })` 只做**追加**——已有内容原样保留，新条目经 `md_docs.formatRelationshipBlock` 序列化后贴在末尾；文档缺失/为空时先按该层模板起底（书/章 `CHAPTER_RELATIONSHIPS_TEMPLATE`、卷 `VOL_RELATIONSHIPS_TEMPLATE`，模板注释被 `stripComments` 剥离、不影响解析）。当前唯一调用方是人物关系面板「添加人物」（写人物后按同一级别写关系，status 默认 `active`）。
- **《时间线.md》条目（v0.2.x+，书/卷/章三层通用）**：纯 Markdown 块——每个 `## <时间点>` 标题＝一个时间点——先按 TL_DATE_MD_RE 匹配 `年` / `年-月` / `年-月-日`（如 `-129`、`-129-06`、`-129-06-15`），不中再回落 TL_TIME_RE 纯数字校验（负数/小数/科学计数亦可）；两者皆不合的标题块整块跳过、不影响其后有效块；块内字段行 `- 人物：A、B`（别名 `- 角色：`）顿号切分涉及角色、`- 事件：<文字>` 记事件描述（字段行可带内联值，其后的自由文本行或 ```text 围栏内容一并并入 event），其余字段行（如 `- 发生章节：`）忽略。物理位置与探测次序：书根仅裸名 `<书名>/时间线.md`；卷目录新格式 `<卷名>-时间线.md`→缺失回落裸 `时间线.md`；章节目录新格式 `<NN-标题>-时间线.md`→裸 `时间线.md`。**已列入各层默认文档模板清单**：story_types.timelineTemplate(h1Title) 空模板（内含写法示例注释）随建书/建卷/建章播种，ensureRootDocs/ensureVolumeFolder/rescan 补缺时同样补它（已有内容原样保留）；**由时间线面板只读消费**——main.ts getTimelineSnapshot 把三层条目合并为单一按 (年,月,日) 升序的时间轴 + story_manager.readTimelineDocs 全程非交互枚举＋md_docs.parseTimelines 解析；不参与提示词注入。parse/format 往返一致（formatTimelines 输出再 parse 无损）。**物理命名映射完整性坑（v0.2.x 缺陷已修）**：章/卷目录内每个逻辑基名都必须在 CHAPTER_DOC_SUFFIX / VOLUME_DOC_SUFFIX（及反向 *_SUFFIX_TO_BASE）有后缀条目，否则 chapterDocPhysicalName/volumeDocPhysicalName 拼出 `<前缀>-undefined`（无扩展名）落盘——《时间线》曾漏配导致建章/建卷播种误建 `NN-标题-undefined`／`卷名-undefined`；「时间线.md」→ 后缀 "时间线.md"（物理名即新格式探测名）。chapterLogicalBaseOf / volumeLogicalBaseOf 现识别 `-undefined` 残留文件为《时间线》，切书时 detectOldFormatDocs → confirmBox → migrateOldFormatDocs 批量重命名为正确新格式（目标名已被同目录另一文件占用则跳过该条避免冲突，残留留待手动清理）；新增模板文档时务必同步四处映射＋两个 TEMPLATE_BASES 集合。
- 新建书/章时缺失的设定文档自动创建为「HTML 注释示例」模板（`ensureDoc`：已存在则跳过、绝不覆盖用户内容）；所有读取器在解析前过滤 HTML 注释，示例不会污染状态。大纲类文档模板：`outlineTemplate(书名)` → `# <书名> 大纲` + 全书主线/卷划分/结局示例注释；`chapterOutlineTemplate(num,标题)` → `# 第N章 <标题> 大纲` + 本章目标/情节要点/结尾示例注释；两者末尾均经 `appendOutlineMarkerHelp()` 附「大纲详略标记使用帮助」（[详][扩][补][略][跳]/[伏] + `<角色：>`/`<场景：>` 用法）。写盘路径同样恒带尾注：`setChapterOutline` / `appendChapterOutline`；建书/重扫描/open-outline/open-chapter-outline 均按书名或章节号动态生成模板标题行。
- 多行内容（场景正文、世界观历史/力量体系等）用 ```` ```text ```` 围栏包裹，解析按围栏进行（见 `md_docs.ts`）。
- **字段命名陷阱（勿单方面"修正"）**：角色文档 `CharacterDoc` 的章节归属字段叫 **`chapter`**，而场景文档 `SceneDoc` 叫 **`chapter_num`**。两边都要改才允许统一。
- 伏笔（`ForeshadowItem`）：字段=章节/**复合键字符串**（v0.0.15 起，如 `"3"` / `"v02:5"`；旧纯数字解析为根域）/人物/事由/是否完成；`index` 是**章内序号（0 起）**，由 `parseForeshadows` 从标题推导、保存时按位置重排（`saveOutlineForeshadows` 先做 per-chapter 归一化再写盘）。标题格式：根域 `## 第N章 伏笔K`（不变）、卷域 `## <卷名>·第N章 伏笔K`。[伏]…[/] 提取的「章节」字段支持两式：`章节：N`（默认归属当前写作章所在容器）与显式跨卷 `章节：<卷名>第N章`（saveOutlineForeshadows 用已知卷名解析，无法解析则丢弃并计数告警）。定位一律「复合键+序号」、不带序号默认 0。
- 文件名/目录名统一经 `safeFilename()` 清理，禁止手工拼接未清洗的用户输入。
