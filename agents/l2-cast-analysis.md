# L2 · 人物与场景分析（/analyze-cast）

## 模块概要

命令 `analyze-cast`：**AI 深度分析**——逐章调用 LLM 分析正文，提取该章出现的人物 / 场景 / 人物关系（严格 JSON），代码侧跨章聚合出每个条目的「出现范围」。按 span 定层与写盘计划，把条目写入书/卷/章三层的《人物.md》《场景.md》，并把新关系追加到对应层《人物关系.md》。纯逻辑在独立模块 `src/cast_analyzer.ts`（提示词构建 + JSON 解析 + 聚合 + 定层 + 写盘计划，不接触 Vault）；vault IO 走 `story_manager.ts` 的分层读写方法；LLM 流式与面板交互在 `main.ts` `cmdAnalyzeCast`。

## 行为约定

- **逐章分析后聚合**：每章一次 LLM 调用（返回该章的人物/场景/关系 JSON），全部章处理完后才由代码聚合出现集合并定层——单章视角无法判断跨章/跨卷范围，故中途不得提前写盘。
- **分层规则（span 判定，平铺/卷模式通用）**：容器 = 章节复合键的归属卷（无卷 = 书根；平铺模式强制全部归书根）。≥2 个不同容器 → 书级；单容器内 ≥2 章 → 该容器级（书根→书级、卷→卷级）；仅 1 章 → 章级。卷模式下书根直属章（无卷）同样参与容器计数。
- **关系落层同 span 规则**：按「关系被描绘到的章节」归属——只在某章出现存章级、多章（同卷）出现存卷级、各卷都有存书级；**不是**取两个人物所在层的公共祖先。
- **合并语义（幂等自归位）**：同名人物/场景条目若已存在于任一层，**移动**到新判定层并从原层移除（多层同时存在时以最具体层 章>卷>书 为合并基座、其余副本全删），字段级合并——现有非空值优先、缺项补新值（`pick` 助手：解析器缺项产出 `""`，故不能只用 `??`）；场景 `content`（用户手写正文）只保留基座值、绝不从分析回填。关系纯追加：按排序 A-B 对去重，三层中已存在的对跳过（`appendRelationships` 本身不去重、空列表抛错，过滤必须在调用前完成）。
- **移动时的编号复位**：落到书级/卷级 → `chapter`(人物) / `chapter_num`(场景) 置 0（格式化时省略该字段）；落到章级 → 目标章的本地章号（`parseChKey(chapterKey).num`）。
- **写盘策略**：仅重写内容有变化的层（规范 JSON 键排序比较，与条目顺序无关）；关系按层分组后逐层 `appendRelationships`。
- **单章失败不中断**：每章经面板流式输出，JSON 解析失败最多重试 3 次（带纠正说明重新流式，重试间 `view.reset()` 清屏而非 fail——`streamWithEmptyRetry` 已在 3 次空输出时自行 fail，不得重复 fail）；最终仍失败的章跳过并列入收尾 Notice 汇总，整轮继续。
- **中止语义**：点「停止生成」/流式中关面板中止 → 聚合未完成 → **零写盘**（出现范围信息不完整，部分写盘会产生错误分层）。
- **跨章名归一辅助**：每章提示词注入「已知人名/场景 id」累积清单（含运行前从磁盘三层文档播种的存量条目），帮助 LLM 跨章使用同一名字。
- **空章跳过**：正文为空的章直接跳过并在汇总中列出，不发起 LLM 调用。
